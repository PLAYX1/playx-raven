# 홈 한 화면 정리 결과

기준: `claude/desktop-simple`, 시작 HEAD `ed78953`. 한국어 기본 화면, CSS 픽셀 100% 기준. 실제 지갑·송금·시드·비밀번호·키를 사용하지 않고 합성 fixture로 검사했다. push와 태그 생성은 하지 않는다.

## 전 → 후

제공된 `6.png`, `7.png`를 확인했다. 이전 홈은 라비가 넓은 왼쪽 영역을 차지하고 오른쪽에 잔액·안전·가게·활동·대화가 세로로 쌓였다. 라비 몸 높이 220~360px, 64px 단추, 큰 카드 여백과 홈 하단 120px 여백이 겹쳐 활동·대화·잠금 안내를 스크롤해야 볼 수 있었다. 직전 커밋의 오른쪽 카드 폭 수정은 시작점에 포함되어 있었다.

변경 후에는 같은 폭의 두 열, 세 행으로 정렬한다.

| 행 | 왼쪽 | 오른쪽 |
|---|---|---|
| 1 | 완료 잔액, 보내기·받기·더 보기 | 백업·잠금·서버 신호등 칩, 백업 확인 |
| 2 | 작은 라비, 상태, 한 줄 인사, 대화 열기 | 오늘 받은 금액·판매·새 주문·입금 대기 4개 숫자 칩, 더 보기 |
| 3 | 최근 활동 3건, 모두 보기 | 라비 답변/안내 및 대화방 소개 최대 2개 요약, 대화 열기 |

모든 카드에 12px 내부 여백, 같은 1px 외곽선과 16px 모서리를 적용했다. 열 사이·행 사이 간격은 10px이다. 잔액은 크게, 숫자는 고정폭 숫자 정렬로 표시한다. 라비 몸은 `clamp(88px,12vh,132px)`로 창 높이에 비례한다. 중복 잔액과 긴 소개는 홈에서 숨기고 기능은 기존 상세 화면/라비 도구에서 이용한다. 활동의 모두 보기는 지갑 거래 내역으로 이동한다. 가게의 발송·환불 등 상세는 더 보기로 이동한다.

잠금 안내는 카드 격자 전체 폭과 정렬되며 기존 지갑 열기 단추를 유지한다. 페이지 overflow를 숨겨 통과시키지 않는다. 1050px 이하에서는 DOM 순서 그대로 한 열로 배치해 정상 스크롤을 허용한다. 양의 tabindex나 CSS order로 카드 순서를 바꾸지 않았다. 홈 글자는 15px 이상, 조작 단추는 44px 이상이다. 새 문구에 영어·일본어·중국어 번역도 추가했다.

안전 칩은 `wallet_lock_state`, `backup_survey`, `node_status`의 읽기 결과를 사용한다. 백업은 로컬 사본 확인이라는 범위를 표시하며 외부/클라우드 백업 완료를 단정하지 않는다. 모르는 상태와 조회 오류를 정상으로 만들지 않는다. 가게 없음과 조회 실패를 구별하고, 입금 대기 조회 실패는 0 대신 확인 못 함으로 표시한다. 상태는 홈에서 20초마다 갱신한다.

## CSS 산술 검증

`npm run check:home-onescreen`을 `check:pre-release` 및 배포 전 목록에 연결했다. CSS를 PostCSS로 읽어 행의 clamp 최소/상한과 해당 창에서의 실제 적용 높이, 카드 내용 최소 높이, 양쪽 열 폭, 글자/단추 최소 크기, sRGB 대비를 계산한다. 높이 증가·열 비율 변경·저대비 색으로 변이하면 검사 자체가 실패하는 것도 확인했다.

다음 값은 **브라우저 측정이 아닌 CSS 산술**이다. 총높이에 제목줄/헤더 110px, 본문 상하 24px, 홈 제목/간격 36px, 잠금 배너/간격 64px를 포함한다. 배너가 없으면 64px가 줄어든다. clamp의 전체 상한은 176/184px이며, 작은 창에서는 viewport 식과 최소값으로 제한된다.

| 창 | 카드 3행 높이 | 좌/우 카드 폭 | 배너 포함 총높이 | 남는 높이 |
|---|---|---|---|---|
| 1120×780 | 148 / 148 / 220 | 487 / 487 | 770 | 10 |
| 1440×900 | 162 / 162 / 220 | 647 / 647 | 798 | 102 |
| 1920×1080 | 176 / 184 / 220 | 887 / 887 | 834 | 246 |

검사한 카드/칩/버튼/배너 텍스트 색 조합의 최소 대비는 5.49:1이다. 실제 production 함수 fixture로 활동 3건 제한, 대화 2개 제한, 숫자 칩 4개, HTML escaping, 가게 없음/오류, 잠금·백업 상태 분기를 검사했다. 가게 조회 실패를 가게 없음으로 삼키던 처리는 이 검사에서 발견해 수정했다.

## 검사 결과와 미검증 항목

- `npm run check:pre-release`: 통과. preflight, TypeScript, Vite, 첫 실행, 라비 companion, 새 홈 검사 포함.
- 기존 추적된 JavaScript 검사 50개: 35개 통과, 의도적 변이 검사 1개에서 요구한 assertion 실패 확인 및 원본 복원, 14개는 브라우저 실행/루프백 바인딩 차단으로 미완료. 설치 프로그램 검사는 오프라인 의존성으로 재실행해 통과했다. 상세 목록은 `artifacts/home-onescreen/verification.json`.
- 네이티브 전체: **757 통과 / 7 실패 / 13 무시**. `RV_BACKUP_FIXTURE_ROOT=/tmp/home-onescreen-native`로 합성 데이터 경로를 격리했다. 남은 7개는 모두 루프백 소켓 bind의 EPERM이다. 처음에는 fixture 환경변수 누락, 이후 `/private` 경로 글자를 비밀정보로 오인하는 시험 실패가 있었고 시험 경로 설정으로 해결했다. 제품 코드를 약화하거나 해당 시험을 통과로 바꾸지 않았다.
- 복구 안전 Rust 검사: 23개 통과. 복구 벡터 `--no-core`: 30개 통과. 기본 벡터의 Core 구간은 포트 차단으로 미검증.
- Python 변이: browser seal과 refund는 의도한 assertion 실패 및 원본 복원 확인. refund는 시험 하네스의 fixture 부모 경로만 `/tmp`로 치환했다. desktop security 변이 검사는 기존 소스 기준 문자열을 찾지 못해 실패했다. security usability 변이는 일부 assertion 실패를 확인했지만 루프백 EPERM에서 중단되어 전체 통과가 아니다. 시험 원본/제품 소스는 복원했다.
- 시작 때부터 미추적이던 `check-game-bridge.mjs`는 native bridge 연결 assertion에 실패한다. 이번 홈 커밋에는 해당 작업과 파일들을 넣지 않았다.

격리 프로필의 헤드리스 Chrome 자체 실행은 `Failed to launch the browser process!`로 실패했다. 기존 브라우저 검사 중 서버를 먼저 여는 것들은 `listen EPERM 127.0.0.1`로 차단됐다. 기존 프로필 충돌은 새 artifact 경로로 재시도해 실제 EPERM까지 확인했다. **실제 스크린샷, 폰트 줄바꿈, 긴 금액/긴 번역, 확대 배율, 브라우저 CSS cascade, Tauri WebView, 키보드·스크린리더 실사용은 미검증이다.** 특히 최소 창 여유는 10px이므로 브라우저 확인 전 실측 무스크롤을 단정할 수 없다. 대화방 요약은 기존 `talk_rooms`가 제공하는 방 소개이며 최신 메시지를 새로 조회하지 않는다.

따라서 “모든 기존 검사 통과” 조건은 현재 환경에서 충족하지 못했다. 환경 차단과 기존 검사 결함을 숨기지 않고 기록한다. 홈 관련 구현과 산술/fixture 검증은 완료했다.

## 전달

이번 작업 파일만 임시 `GIT_INDEX_FILE`에 올려 커밋한다. 원래 worktree의 `COMMIT_EDITMSG` 쓰기가 EPERM으로 차단되어, Git worktree 메타데이터도 `/private/tmp`에 두고 기존 공용 객체/브랜치를 사용한다. 원래 인덱스는 변경하지 않는다. 기존 작업트리/인덱스의 다른 작업은 포함하지 않는다. 커밋 후 `artifacts/home-onescreen.bundle`을 생성하며 시작 HEAD `ed78953`이 필요한 증분 Git 번들이다. `git bundle verify artifacts/home-onescreen.bundle`로 확인한다. 번들 자신의 체크섬과 커밋 정보는 커밋 이후 생성되는 `artifacts/home-onescreen/delivery.json`에 기록한다.
