# 0.6.0 공동구매 · 대기 신청 · 가게 사정 환불 · 송장 (handoff)

브랜치 `claude/desktop-simple`. 설계서 RV7 §16·§17·§18·§22 그대로.

## 들어간 것
- `src-tauri/src/groupbuy.rs` (새 파일) — 규칙·저장(`groupbuy.json`)·명령 5개(`gb_overview` `gb_window_set` `gb_wait_cancel` `gb_refund_mark` `gb_ship_set`). 시험 14개.
- 공동구매 = 메뉴 품목 + `group: {pickup, deadline, min}`. 최대 수량은 원래 `stock`.
- **남은 수는 결제 장부로 센다**: 메뉴 `stock` 은 화면이 가게를 다시 올리거나 앱을 다시 켜면 원래 숫자로 돌아가서, 한 달짜리 공동구매에서는 초과 판매가 된다. 그래서 공동구매 품목은 `stock.rs` 차감을 건너뛰고 `groupbuy::adjusted_menu` 로 센다. (보통 품목의 같은 문제는 그대로 — 하루 장사라 영향이 작다. 따로 고칠 것.)
- 서버: 마감 다음 날부터 주문 거절(`can_order`, 가게 시계 기준) · `/api/wait`(신청·순번) · `/api/wait/cancel` · `/api/ship` · 주문 상태에 `ship` · 결제 확정 때 확정자 명단에 적기.
- 손님 화면(`web/customer.html`): 공동구매 줄(받는 날·마감·최소), 다 차면 「대기 신청」 시트(연락처 필수, 돈 없음), 내 대기 순번 띠, 결제 차례면 「n개 담기」로 바로 주문(대기 번호가 주문에 묶임), 발송 뒤 송장·「배송 조회」 링크.
- 사장 화면: 「내 가게 → 공동구매」 탭(품목 정하기·결제 차례 시간·현황·대기·환불 미리보기·송장 넣기), 홈 「오늘 가게」에 환불 대기·결제 차례 알릴 분·송장 넣을 주문 줄.

## 대표 결정을 지키는 곳
- 결제한 예약에는 손님 쪽 취소·환불 단추가 **없다**. 대기 신청만 취소된다.
- 환불은 마감 뒤 최소 미달일 때만 목록에 오르고, 기존 환불 창(주소·금액 확인 → 「되돌릴 수 없습니다」 확인)으로 사장이 보낸다. 자동 송금 없음.
- 결제 차례 기본 24시간, 사장이 1시간~14일로 바꿈. 지나면 다음 사람.
- 대기 연락처는 가게 컴퓨터에만 있고 손님 응답에는 안 나간다(시험이 지킴).

## 확인한 것 / 못 한 것
- ✅ `groupbuy.rs` 시험 14개(따로 떼어 리눅스 cargo 로 실행), 화면 타입 검사, preflight, 손님 화면 스크립트 문법.
- ❌ 전체 `cargo test`(Mac 필요), 실제 창에서 공동구매 한 바퀴(품목 만들기 → 손님 결제 → 다 참 → 대기 → 자리 남 → 차례 결제 → 마감 미달 → 환불), 택배사 조회 링크 5곳이 실제로 열리는지.
- ⚠️ 택배사 조회 주소는 각 회사가 바꾸면 깨진다(번호는 그대로 보인다).
- ⚠️ 한 주문에 공동구매와 다른 품목을 섞으면 환불 미리보기 금액은 수량 비율 어림이다 — 사장이 금액을 확인하고 고친다.
