# 라비 에이전트 1단계

2026-10-06. 기준 커밋 `690679d`, 앱 버전 0.7.1. 이전 실행의 미커밋 초안을 이어 수정했다. 새 의존성, 실제 AI 요청, 실제 송금, 메인넷 거래는 없다.

## 구현

앱 시작 시 저장된 AI 제공자를 확인한 뒤 가장자리에서 중앙으로 라비가 들어온다. 착지 후 「짜잔! 오늘 어땠어요?」와 로컬 요약을 표시하고, 클릭하거나 18초가 지나면 기존 대화창으로 도킹한다. 요약이 도착하면 읽을 시간을 다시 준다. 자동 도킹은 입력 초점을 가져가지 않는다. 세션 저장소와 메모리로 중복 등장을 막고, 설정의 「시작 인사 끄기」는 다음 시작부터 적용한다. reduced-motion에서는 이동을 페이드로 바꾼다. 기존 `.rv-lid` 기본 접힘 규칙을 유지한다.

잠긴 지갑은 잠금 상태와 직접 잠금을 풀라는 안내만 표시한다. 열린 지갑은 읽힌 잔액·오늘 주문·매출·백업·동기화만 표시한다. 읽지 못한 값은 데이터 없음으로 처리하고, 혼합 통화나 읽을 수 없는 장부 행이 있으면 순매출 합계를 제시하지 않는다. 요약은 외부 AI 없이 작동한다. AI 키와 저장된 정보 동의가 모두 있는 경우에만 동의한 범위의 요약으로 짧은 인사를 요청하며 실패하면 기본 인사를 유지한다.

| 도구 | 결과·동작 | AI 전달 동의 |
|---|---|---|
| `wallet_balance` | 확인·미확인 RVN 잔액 | 잔액 |
| `recent_transactions` | 최대 10건, 방향·금액·확인 수·시각 | 최근 거래 |
| `rvn_price_krw` | 기존 시세 함수의 KRW 시세·불안정 여부 | 첫 사용 정보 선택 |
| `shop_sales` | 오늘 또는 최대 31일의 매출·환불·순매출 | 가게 |
| `shop_orders` | 오늘 결제·환불·입금 대기 수, 최근 상태·시각 | 가게 |
| `node_status` | 블록·동기화·연결 상태 | 첫 사용 정보 선택 |
| `backup_status` | 마지막 성공 백업 시각, 경로 제외 | 첫 사용 정보 선택 |
| `fee_status` | 개발비율·미전송액·전송 누계·설정 준비 여부 | 가게 |
| `prepare_send` | 직접 적은 주소·금액으로 기존 보내기 확인 화면 준비 | 직접 요청 |
| `open_screen` | 기존 `RAVI_SCREENS`의 7개 화면 중 요청한 화면 | 직접 요청 |
| `prepare_promo` | 기존 홍보 도우미 열기 | 직접 요청 |

설정과 라비 도구 영역의 로컬 조회는 AI에 전송하지 않으므로 AI 전달 동의·키 없이 쓸 수 있다. 잠금 차단은 로컬 조회에도 적용한다. 자유 질문 에이전트는 AI 키가 있을 때만 동작한다. 기존 오프라인 안내, 홍보 카드, 송금 검증과 직접 승인 흐름은 유지한다.

## 안전 장치

- Rust 허용 목록에서 이름·필수 인자·유형·범위·추가 인자·결과 크기를 검증한다. 임의 RPC/명령, 잠금 해제, 서명, 송금 확정, 비밀 반환 도구는 없다.
- 한 줄 JSON 계약으로 기존 제공자 전송 코드를 사용한다. 최대 4회 AI 요청, 요청당 입력 24,000바이트, 응답 4,096바이트, 제공자 출력 600토큰, 전체 60초를 제한한다. 로컬 도구는 12초, 시작 요약은 잠금 조회 4초와 병렬 도구 조회 각 4초, AI 인사는 전체 15초를 제한한다.
- `ai_budget`의 Owner 사용량을 실제 요청 전에 차감한다. 실패한 요청도 차감하며 한도·동시 실행 제한을 우회하지 않는다.
- 첫 사용 동의의 세 범주는 기본 꺼짐이다. 동의하지 않거나 질문과 관계없는 범주는 읽지 않는다. 설정 변경은 진행 중인 대화에서도 재확인한다.
- 외부 문자열을 그대로 복사하지 않고 숫자·불리언·허용된 상태만 투영한다. 주소, 주문 메모, 고객명, 가게명, 경로는 AI 도구 결과에서 빠진다. 결과는 명시적 데이터 구분자 안에 JSON으로 전달한다.
- 준비 권한은 이번 사용자 원문에만 결부한다. 도구 결과·AI 답·대화 이력은 권한 근거가 아니다. 송금은 원문 주소와 RVN 금액이 일치해야 하며, 거절·방법 문의 표현은 준비하지 않는다. 준비 응답 뒤에는 루프를 즉시 종료한다.
- 송금 준비는 기존 `applyActions` → 보내기 검증·확인 화면을 사용한다. 실제 확정 단추는 사용자가 직접 누른다.
- 감사 기록은 도구 이름·시각·성공 여부 세 필드만 0600 파일에 최대 200개 저장한다. 알 수 없는 이름은 `rejected`로 대체한다. 인자·결과·주소·금액은 저장하지 않는다.
- 입력·출력의 기존 비밀 검사, AI 키체인 처리와 오류 가림 처리를 유지한다. 새 의존성을 추가하지 않는다.

## 검증과 한계

기계 판독 결과는 `artifacts/agent1/`에 있다. `npm run build`, `check-ai-safety.mjs`, `check-send-confirmation.mjs`, 브라우저를 요구하지 않는 기존 `check-ravi-*.mjs`를 통과했다. 60/120문항·유사도·상태·홍보·키·대화창 검사를 포함한다.

`scripts/check-ravi-agent.mjs`는 실제 TypeScript를 VM에서 실행해 시작 인사·세션·끄기·동의·로컬 조회·키 카드·기록·준비 연결을 검사한다. 실제 Rust 루프를 사용하는 새 시험 8개도 실행한다. Rust 시험의 AI/RPC 서버는 Axum HTTP 요청/응답을 메모리에서 처리한다. 소켓을 열거나 실서비스에 접속하지 않는다. 정상 루프, 각각의 읽기 도구, 잠금, 최소 요약, 동의 거절·변경, 악성 주문 메모, 쓰기 준비, 잘못된 이름·인자·형식, 단계·입력·응답·시간 상한, 실제 예산 모듈의 요청 전 차단과 감사 필드 제한을 검증한다.

전체 Rust 시험은 먼저 요청한 `$HOME/rv-test-fixture`로 실행했으나 샌드박스의 폴더 생성 거부 때문에 실패했다. `/tmp/rv-test-fixture`로 재실행했다. 최종 전체 실행은 **738개 통과, 7개 실패, 기존 13개 무시**다. 실패 7개는 모두 `Operation not permitted`로 로컬 소켓 바인딩이 거부된 기존 시험이다. 해당 7개를 명시적으로 제외하고 `--test-threads=1`로 실행한 별도 검사는 **738개 통과, 실패 0, 무시 13, 제외 7**이다. 전체 통과를 주장하지 않으며 시험 본문을 약화하거나 실패를 성공으로 바꾸지 않았다.

환경에 막힌 기존 Rust 시험:

- `ai::connection_tests::loopback_mock_covers_http_refusal_and_delayed_response`
- `ai_endpoint::tests::redirects_cannot_forward_a_question_to_another_destination`
- `peers::tests::폴더_주소도_파일처럼_살아_있다고_본다`
- `relay::tests::live_push_and_pairing_rooms_stay_off_disk`
- `server::bind_probe::binding_the_phone_port_is_fast`
- `server::wallet_usability_tests::actual_loopback_listener_supplies_peer_and_never_trusts_forwarding_headers`
- `upload::photo_security_tests::streaming_size_mime_and_magic_are_checked_without_length`

기존 브라우저 검사 3개는 Chrome 실행 실패로 미검증이다. 새 검사도 Chrome 실행 실패를 별도 미검증으로 기록한다. 따라서 실제 화면의 곡선 움직임·착지 품질·배치·비활성 창의 눈, Tauri/WKWebView/WebView2 실기기와 제공자별 실제 응답은 미검증이다. VM은 동작과 CSS 계약을 검증하지만 픽셀 검증을 대신하지 않는다.

1단계의 송금 준비 문법은 의도적으로 좁다. 주소와 `1 RVN`처럼 숫자·단위가 명시된 요청을 사용하며, 생략·별칭·자산 송금·복합 작업은 확장하지 않았다. 백업 도구는 성공 시각, 주문 도구는 오늘 결제·환불과 현재 입금 대기 요약만 제공한다. 이 단계에서 규칙 자동 작업이나 실제 자동 쓰기는 추가하지 않았다.

## 전달과 다음 단계

임시 `GIT_INDEX_FILE`로 이 단계 파일만 커밋하고 `refs/heads/claude/agent1`을 만든다. 현재 작업 브랜치·기본 인덱스를 바꾸지 않는다. `artifacts/agent1.bundle`은 기준 `690679d` 위의 증분 번들이며 push·태그는 하지 않는다. 이전 작업의 별도 번들과 기존 회귀 결과 파일 변경은 이 커밋에 섞지 않는다.

2단계는 같은 Rust 도구 계약의 폰·웹 이식, 사용자가 명시적으로 설정한 규칙 기반 자동 조회·알림, 주소·단위 해석과 복합 요청을 포함한 송금 준비 심화 순서로 제안한다. 실제 송금 확정은 계속 직접 승인으로 유지한다. 먼저 소켓·Chrome 사용이 가능한 시험 환경에서 남은 검증을 완료해야 한다.
