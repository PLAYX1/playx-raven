# 체인 POS — 매장 10~100곳의 레이븐볼트 데스크탑 (11-11, 대표·페이블 판정)

대표 11-11: 「레이븐볼트를 각 매장에서 운영 POS 로」「매장 100개 할 수도 있잖아」「당연히 다 해야 해」.
사업자: 매장마다 따로 있거나, 한 사업자 아래 종된 사업장일 수 있다 — **둘 다 지원.**

## 원칙 (페이블 판정)

1. **12단어는 본점 한 곳에만.** 매장 PC 에는 12단어 입력 화면이 없다. 100곳에 같은 12단어 = 금고 100부(설계를 정하는 가장 큰 위험).
2. **매장 POS 는 완전 로컬.** 인터넷·릴레이가 끊겨도 주문·결제 기록이 계속 쌓인다.
3. **본점으로는 서명·암호화된 매출 로그만** 별 모양으로 올린다. 100×100 연결 없음.
4. **매장 PC 에 돈을 두지 않는다.** RVN 받는 주소 = 사장 주소. 보내기 승인은 본점 1곳.
5. **카드 승인·현금영수증·세금계산서는 하지 않는다**(VAN·PG·국세청 몫). 레이븐볼트는 결과(금액·승인번호·발급번호)만 기록.

## 안 만드는 것
카드 직접 승인 · 세금계산서 발급 · erasure coding · 매장끼리 전부 연결 · NIP-26 · 매장 PC 자동 승인 · 본점 보관(custody) · 실시간 재고 동기화.

## 순서

### ① 매장 열쇠 발급·끊기 (이 문서의 첫 구현)
- **매장 열쇠:** 본점 12단어에서 `m/44'/175'/7'/3'/<n>'/<세대>'` (n = 매장 번호 1..9999, 세대 0..63). 매장마다 다른 열쇠, 본점이 언제든 다시 뽑을 수 있다. 끊긴 열쇠는 다시 주지 않는다 — 같은 번호를 다시 발급하면 다음 세대.
- **본점(체인) 열쇠:** `PATH_CHAIN_KEY = m/44'/175'/7'/4'/0'` — 가게 간판 열쇠와 **따로**(간판 열쇠는 `store_sign_digest` 로 아무 다이제스트에나 서명하므로 같으면 위조 통로가 된다 · 페이블 11-11 검토).
- **끊기는 열쇠 단위:** 한 매장 증서를 끊으면 같은 매장 공개키로 나간 증서가 모두 끊긴다. 끊기도 Rust 확인 창을 거친다.
- **릴레이 겉봉투 = 체인 열쇠 서명**(사장 이야기 이름과 묶지 않음). 공개 명부에 사업자 번호를 싣지 않는다.
- 🔸 이웃 매장끼리 증서를 확인하는 단계(②~⑤)에서는 끊기 목록 `seq` 후퇴 금지(`lan_cert::accept` 규칙)를 반드시 쓴다.
- **매장 증서:** `lan_cert` 모양 그대로, 도메인만 `ravenvault-chain-v1`. 본문 = `{v:1, chain:<본점 공개키>, store:<n>, name, storeKey:<매장 공개키>, biz:{no, sub?}, role:"store", scope:["pos","talk","shop-read"], serial, issuedAt, notAfter}`. 만료 1년, 본점이 켜져 있으면 30일 전 자동 갱신(②③ 뒤).
- **설치 꾸러미:** 매장 비밀 열쇠 + 증서를 **일회용 설치 암호(6단어, 본점 화면에만 보임)** 로 봉함(xchacha20poly1305, 이미 쓰는 크레이트). 파일 또는 QR 로 매장 PC 에 옮긴다. 꾸러미에 12단어는 없다.
- **매장 PC 합류:** 「본점에서 받은 꾸러미 열기」 → 설치 암호 → 매장 열쇠·증서를 앱 폴더에 0600 저장(`chain/store.json`). 이 PC 는 12단어 없이 POS 로 켜진다.
- **끊기(도난):** 본점이 끊기 목록(`lan_cert` 철회 목록 모양, 도메인 동일)에 serial 을 넣어 서명 → Nostr kind 30078 `d=ravenvault-chain-revocations` 로 올리고 본점 로컬에도 둔다. 본점·이웃은 끊긴 매장의 push·서명을 거절.
- **명부:** kind 30078 `d=ravenvault-chain-roster` (본점 키 서명) — 매장 번호·이름·매장 공개키·사업자 번호 목록. 캐시일 뿐, 판정은 증서·끊기 목록으로.
- 하위자산(`RV.S.<체인>/n`) 박기는 ①에서 하지 않는다(100 RVN 비용 — 대표 결정 뒤).

### ② POS 결제 칸 + 끊겨도 쌓이는 기록
결제수단(카드 승인번호·현금·현금영수증 번호·RVN+원화 환산), 영수증 번호, 매장 사업자 번호(+종사업장 번호). `lan/log/<매장>` 과 같은 덧붙이기 로그.
- **구현(11-11, `pos_pay.rs`·`src/pos-pay.ts`):** 로그 = `pos/log/<범위>/<YYYYMM>.jsonl` + `head.json`(범위 = `chain-<본점 지문16>-<n>` 또는 `shop`). 줄마다 `seq`(= 영수증 번호, 0 = 로그 시작 줄)·`prev`(앞 줄 정본 JSON SHA-256). 체인 매장은 줄마다 매장 열쇠 서명(도메인 `ravenvault-chain-sale-v1`, `key` 칸). 취소 = 원래 줄을 가리키는 `void` 줄(전액, 한 번만). 잘린 로그라도 번호는 `head.json` 다음부터(재사용 없음).
- **프로그램 사이 잠금(11-11 보강):** 로그 폴더마다 `writer.lock` 에 운영체제 배타 잠금(std `File::try_lock` = unix flock · 윈도우 LockFileEx, 새 크레이트 없음)을 쥔 프로그램만 쓴다. 레이븐볼트가 두 번 켜지면 두 번째 쪽 기록·취소는 「다른 레이븐볼트 창이 이 매장의 결제 기록을 쓰고 있어요…」로 거절(보기만은 파일을 새로 읽어서 된다). 프로그램이 죽으면 운영체제가 풀어 주므로 오래된 잠금 판정은 필요 없다. ③ 본점 받기·꺼짐 확인도 `chain/sales/.lock`(받기는 최대 2초 기다린 뒤 503 busy), 매장 보내기는 `chain/push.lock`.
- RVN 주문은 매출장부(`ledger::settled_order`)에 원화로 얼린 금액·txid 가 있으면 그것을 쓴다(지금 시세로 다시 재지 않음 · `krwFrom:"order"`). 없으면 직원이 txid·금액을 적는다(`krwFrom:"staff"`). 같은 주문은 한 번만.
- 체인 아닌 가게의 사업자 번호 = `pos/settings.json`. 체인 매장은 증서의 `biz` 만(바꿀 수 없음). 증서 만료·끊김이어도 기록은 쌓는다(판정은 ③ 본점).

### ③ 본점으로 매출 보내기 + 합계 + 꺼짐 알림
10분마다 매장 키 서명·데이터 키 암호화 로그 묶음 push(`/lan/push` 를 증서 있을 때만 터널로도 허용). 3번 연속 끊기면 「○○점 꺼짐」을 본점 화면·사장 폰 쪽지로. 매장별·체인 전체·(종사업장이면) 본점 사업자 단위 합계.
- **구현(11-11, `chain_sales.rs`·`src/chain-sales.ts`):** 길 = `POST /lan/push/chain`(폰 서버 8790, `/lan/push` 기기 복사 v2 와 따로 — 그 길은 그대로 터널 금지). 문 앞 검문은 이 길만 통과시키고, 처리기가 **본점 자신의 끊기 목록**으로 `verify_store_cert` 판정(끊김·만료·모양·서명·발급 기록에 없음 → 403 + `chain/sales/rejects.jsonl`). 본점 PC 가 아니면 404.
- **데이터 열쇠:** HKDF-SHA256(ECDH(매장 비밀, 본점 공개키) = ECDH(본점 비밀, 매장 공개키), info = 본점키\n매장키) → XChaCha20-Poly1305, AAD = 머리 정본 JSON(chain·store·serial·logId·from·count·sentAt·nonce). 답도 같은 열쇠로 봉함(AAD = 요청 nonce) → 가짜 본점의 「다 받았어요」는 믿지 않는다. 본점은 매장 열쇠를 만들 때 그 매장 데이터 열쇠만 `chain/sales-keys.json`(0600)에 둔다(체인 열쇠는 디스크에 없음). ③ 이전 매장은 「받을 준비」(12단어 한 번).
- **받기:** `chain/sales/<n>/<logId>/<YYYYMM>.jsonl` + `state.json`(logId 별 ack·마지막 해시). `verify_records_from(줄, Some(증서 storeKey), (ack+1, 해시))` — 건너뜀(gap)은 받지 않고, 고친 줄·서명 틀림은 앞부분만 받고 경고. 다시 보내도 한 번만. 합계는 본점이 줄에서 직접(취소 줄 음수). 이름·사업자 번호는 본점 issued.json 의 마지막 증서 것.
- **본점 주소:** 매장 PC 설정 칸(`chain/head.json`) — 서명 명부에 싣지 않는다(공개 릴레이에 본점 터널 주소가 퍼지고, 빠른 터널 주소는 켤 때마다 바뀐다). 틀린 주소여도 새는 것 없음(봉함). 모양 = https 공개 이름 · http 는 사설 IPv4/`.local` 만(포트 없으면 8790).
- **꺼짐:** 마지막 받은 때부터 3창(30분) → 본점 화면 「○○점 꺼짐」 + 사장 자신의 이야기 이름으로 **자기에게** NIP-17 쪽지 1통(못 보내면 다음 틱에 다시, 그래도 한 끊김에 한 통). 다시 오면 지운다. 끊긴 매장은 보지 않는다.
- **끊기 목록 전달:** 본점 답(봉함 안)에 본점 끊기 목록을 실어 보내고, 매장은 서명·seq 후퇴 금지(`lan_cert::accept` 규칙)를 넘을 때만 둔다.
- 잠금 화면: 바꾸는 명령(주소 저장·지금 보내기·받을 준비·합계 보기)은 거절. **배경 순환(매장 10분 보내기·본점 꺼짐 확인·쪽지)은 잠겨도 돈다.** 이유:
  ① 잠금은 화면 잠금이지 열쇠 잠금이 아니다 — 매장 비밀 열쇠(`chain/store.json`)·이야기 열쇠(`talkkey.json`)는 원래 디스크에 0600 평문이라, 잠금이 그것을 더 지켜 주지 않는다.
  ② 순환은 새 매출을 만들거나 새로 서명하지 않는다 — 이미 서명된 줄을 봉해 보내고(데이터 열쇠만 씀), 본점은 받기만 한다.
  ③ 쪽지는 사장 **자기 자신**에게만 간다(제3자 없음). ④ 멈추면 문 닫은 밤마다 본점에 「꺼짐」이 잘못 뜬다.
- **보안 검토(11-11) 반영:**
  - 되풀이 막기: 본점이 매장마다 `lastSentAt` 을 두고 `sentAt ≤ lastSentAt` 이면 `replay`, 본점 시계와 1시간 넘게 다르면 `bad-clock`(봉함이 열린 뒤·꺼짐 판정 전). 매장 sentAt 은 늘기만 한다(1시간 넘게 앞선 기록은 지금으로 되돌림).
  - 속도 제한 둘: 인증 전 = 보낸 곳(cf-connecting-ip, 없으면 "lan")마다 1분 **실패** 60번(올바른 요청은 줄이지 않는다, 열쇠 256개 상한·넘치면 overflow 한 칸) / 봉함이 열린 뒤 = 매장(serial)마다 1분 30번. 매장 하나에 로그(logId)는 8개까지.
  - 증서 서명이 맞기 전의 실패(모양·다른 본점·서명·시계)는 전부 `404 not-head` — 본점 PC 인지 알려 주지 않는다. 이 실패들은 줄이 아니라 셈(`chain/sales/junk.json`)으로만 남는다(거절 기록 20줄 창의 고친 흔적을 밀어내지 못하게). 끊김·만료·모르는 증서는 같은 (serial, 사유) 한 시간에 한 줄.
  - 취소 줄: 같은 로그의 매출을 가리키고·수단이 같고·|금액| ≤ 그 매출·한 번만일 때만 합계에서 뺀다. 아니면 사슬엔 그대로 두고(해시 이음) 합계에서 빼며 경고(`void`). 판정표 = `<logId>/index.json`.
  - 달 파일: 본점 시계 + 2일의 달로 자른다(먼 미래 `at` 이 여섯 자리가 아닌 파일 → 영영 안 읽힘을 막는다).

### ④ 백업 두 곳(본점 + 이웃 1곳)
- **매장 로그(k=2):** 매장 PC + 본점(③에서 이미 받는다).
- **본점 chain/ 폴더(k=2):** 본점 PC + 본점이 정한 이웃 매장 1곳(`chain/backup.json` 의 `store`). 구현 `chain_backup.rs`.
  - 담는 것(허용 목록 `allowed_rel`): `issued.json`·`revocations.json`·`backup.json`·`sales/**`(.json·.jsonl 만, 바로가기 안 따라감). 🔴 **담지 않는 것:** `sales-keys.json`·`backup-key.json`(열쇠 — 되살릴 때 12단어로 다시 만든다)·`store.json`·12단어·`backup/`·`held/`.
  - 봉함 = **백업 열쇠** HKDF-SHA256(salt `ravenvault-chain-backup-v1`, ikm = 체인 비밀, info = 체인 공개키) → XChaCha20-Poly1305(AAD = `RVCHB1\n<체인키>`), 안은 gzip JSON. 본점은 체인 비밀이 손에 있을 때(매장 만들기·받을 준비·맡기기에서 없으면 12단어 한 번) 이 열쇠만 `chain/backup-key.json`(0600)에 둔다 — ③ `sales-keys.json` 과 같은 등급. 묶기는 배경에서 6시간마다(받기 잠금 안 — 반쯤 쓴 줄을 담지 않게). 새 PC 에서는 12단어로 다시 만든다.
  - 🔸 체인 공개키에게 봉하기(ECIES)를 쓰지 않은 이유: 공개키는 공개라 **누구나**(맡은 매장도) 그럴듯한 백업을 만들어 바꿔치기할 수 있다. 대칭 열쇠면 봉함이 열리는 것 = 본점(또는 12단어)이 만든 것. 되살릴 때 증서·끊기 목록 서명도 다시 본다.
  - 건네기: 본점 답(봉함 안)에 맡는 매장에게만 요약(해시·크기·때). 다르면 매장이 `{op:"backup", offset}` 으로 384KiB 조각을 받아(한 번 보낼 때 16조각까지) `chain/held/` 에 모으고, 해시가 맞을 때만 바꾼다(끊기면 받은 곳부터). **이웃이 아는 것:** 백업 크기·만든 때·바뀌는 빈도·어느 체인 것인지뿐(내용·매장 이름·금액·사업자 번호는 못 본다).
  - 새 본점 PC: 12단어로 지갑을 되살린 뒤 맡은 매장에서 「본점 백업을 파일로 저장」(`*.rvchainbak.txt`, 봉한 글자 그대로) → 새 PC 「본점 백업 되살리기」 → 체인 비밀로 열고 증서·끊기 목록 서명 확인 → `issued.json` 은 맨 마지막에 쓴다 → 데이터 열쇠 다시 만들기. 이미 본점·매장인 PC 에는 덮어쓰지 않는다. 매장마다 새 본점 주소는 다시 적어야 한다(주소는 백업 대상이 아님).
- **매장 PC 를 바꿨을 때:** 새 꾸러미로 합류 → 「본점에서 이 매장 기록 되찾기」(`{op:"pull"}`, 2000줄씩) → 사슬·서명·시작 줄 확인 → 그대로 깔고 `resume` 줄(새 매장 열쇠 서명, `skip` = 10000) 하나를 잇는다. **다음 영수증 번호 = 되찾은 마지막 + 1 + 10000** — 옛 PC 가 본점에 못 보낸 영수증 번호와 겹치지 않게. 본점·매장 모두 `next_after`(resume 이면 건너뛴 뒤)로 다음 번호를 정한다. 이 PC 에 결제 기록이 한 줄이라도 있으면 거절.
### ⑤ 같은 체인 매장끼리 릴레이 이웃 우선
- 릴레이 이웃(`relay_share`)은 10002 를 올린 **이야기 공개키**로 고른다(매장 열쇠와 다른 열쇠). 그래서:
  - 매장 → 본점(봉함 안 `{op:"relay"}`, 하루 1번·바뀌면): **매장 열쇠 서명** binding `{kind:"relay", chain, store, storeKey, talk, at}`(도메인 `ravenvault-chain-relay-v1`). 본점은 증서 storeKey 서명일 때만 `sales/<n>/state.json` 의 `relay` 에 둔다.
  - 본점 → 매장(`{op:"peers"}`, 답의 `peers` 해시가 다를 때만): `relay-roster.json`(**체인 열쇠 서명**: 끊기지 않은 매장 serial·공개키 + 본점 이야기 공개키 — 매장 만들기·끊기·받을 준비·되살리기 때 다시 서명) + 다른 매장 binding 들. 매장은 명부 서명·자기 끊기 목록·binding 서명을 다 확인한 것만 「같은 체인」으로 치고, 명부 시각이 뒤로 가는 묶음은 두지 않는다(`chain/peers.json`).
  - 🔴 공개 명부(`D_ROSTER`)에는 이야기 공개키를 싣지 않는다 — 체인과 사장·매장 이야기 이름의 연결은 같은 체인 매장끼리만 안다.
- 고르기(`peer_candidates_split` → `pick_peers_pref`): 거르는 규칙(표·14일·§2 주소·내 주소·지운 이웃·사람당 3곳)은 둘 다 먼저 똑같이 거치고, 같은 체인 후보를 먼저 시험해 **8곳 중 최대 4곳**, 나머지는 다른 이웃(시험 총 24번 그대로). 같은 체인 목록을 먼저 보므로 남이 같은 주소를 적어도 그 주소는 같은 체인 몫.
