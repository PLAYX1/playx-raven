# 레이븐볼트 열린 장터 — 「누구나 판매」 2단계 (open seller platform)

작성 2026-10-10. 대표 확정: 「누구나 자기가 500 RVN 내고라도 판매할 수 있는 플랫폼」, 「게임·음악뿐 아니라 책·티켓 등 무엇이든」,
「초보 제작자가 전문 용어 없이 끝낼 수 있는 발행 도우미」, 「쉬운 발행 도구의 대가로 판매 수수료」.

같은 문서가 두 저장소에 있다: 지갑 `ravenvault`(규칙 `core/creator/*`, 브랜치 `claude/rv-open-seller-core`, 기준 `7c73845`)와
데스크탑 `playx-raven`(화면, 브랜치 `claude/rv-open-seller`, 기준 `7b789d8`). 1단계 문서 `docs/creator-publish.md` 위에 쌓는다.

**하지 않은 것**: 실제 IPFS 업로드, 실제 자산 발행(소각), 메인넷 거래, 실제 송금, 소각액의 체인 대조, 외부 핀 서비스 연결, push·배포.
전부 모의 보관소·모의 체인·시험용 일회용 키로만 시험했다. **메인넷 등록 스위치(`REAL_MAINNET_ISSUE_ENABLED`)와 판매 스위치(`OPEN_MARKET_SALES_ENABLED`)는 둘 다 꺼져 있다.**
법률·세무는 판단하지 않았다 — 전부 「전문가 확인 필요」.

> **2026-10-10 이름 방식 변경(대표 확정)**: 장터 자산 이름은 `RV.<종류글자>.<작품이름>` 이다(예: `RV.M.FOREST`).
> 종류 글자 M=음악·G=게임·B=책·T=티켓·X=그 밖의 디지털(X 는 제안, 대표 확인 대기). 이전 초안 접두어(`PLAYXG.`·1단계 `PLAYXG/`)로는 메인넷 발행 스위치가 꺼져 있어 우리가 발행한 자산이 없다 — 옮길 것 없음(옛 이름은 이제 검사에서 거절된다).
> 지갑 브랜치 `claude/rv-asset-name-rv`(기준 `d9ac1c3`), 데스크탑 브랜치 `claude/rv-asset-name-rv-desktop`(기준 `5f95d0b`).

  결과: 레이븐코인 루트 자산 RV.<종류글자>.<이름> (예: RV.M.FOREST · qty 1, units 0, reissuable) + ipfs_hash = 서명된 매니페스트 CID
        보증 500 RVN 소각(수수료 아님, 아무도 받지 않음) + 네트워크 수수료

## 2. 이름 방식: `RV.<종류글자>.<작품이름>` — 제작자가 직접 루트 자산을 발행한다 (대표 확정)

상수 한 곳: `core/creator/asset-name.ts` — `CREATOR_ASSET_PREFIX = 'RV.'`, 종류 표 `ASSET_KIND_LETTER`, 제안 표시 `KIND_LETTER_PENDING`.
소각액은 같은 파일 `BURN_RVN`(저장소 기재값, 원본 미대조).

| 종류 | 글자 | 예 | 상태 |
|---|---|---|---|
| 음악 `music` | `M` | `RV.M.FOREST` | 대표 확정 |
| 게임 `game` | `G` | `RV.G.STAR_RUN` | 대표 확정 |
| 책 `book` | `B` | `RV.B.SEA_BOOK` | 대표 확정 |
| 티켓 `ticket` | `T` | `RV.T.AUTUMN_LIVE` | 대표 확정 |
| 그 밖의 디지털 `digital` | `X` | `RV.X.BRUSH_PACK` | **제안 — 대표 확인 대기**(표 한 줄만 바꾸면 된다) |

- 모양: `RV.` + 종류 글자 한 개 + `.` + 작품 이름. 전체가 **루트 자산 하나**다(500 RVN, 누구나, 주인 표 `RV.M.FOREST!` 는 제작자 지갑에).
- 이름 검증(`checkCreatorAssetName`): 정확한 형식 · 종류 글자는 허용 목록(M·G·B·T·X)만 · 영문 대문자·숫자·`.`·`_` · 점·밑줄 연속/처음/끝 금지 · `/ # ! $ ~` 금지 ·
  전체 30자 이하(`RV.M.` 5자 → 작품 이름 25자) · 예약어 거절. 레이븐코인 규칙은 assets.cpp 정규식을 옮긴 것이며 원본 재대조는 **확인 필요**.
- 예약어 `RESERVED_WORDS = RVN·RAVEN·RAVENCOIN`(데스크탑 create.rs 와 같은 목록). 체인은 **이름 전체**가 이 낱말일 때만 막지만, 우리는 작품 이름의 점으로 나뉜
  어느 칸이든 이 낱말이면 거절한다(`RV.M.RVN`, `RV.M.RAVEN.SONG`). 노드 원본 예약어 목록과 실제 대조는 **확인 필요**.
- **종류 사칭 방지**: 이름의 종류 글자와 매니페스트 `type` 이 다르면 거절한다 — 매니페스트 검사(`manifest-asset`/`kind`, 구매자 목록에서 숨김),
  마법사 사전 검사(`precheck`), 발행 계획(`planIssue({ type })`), 허용 목록 검사, (b)층 조건. 게임을 `RV.M.` 로 내 음악 탭에 끼워 넣을 수 없다(시험).
- **종류별 발견**: `kindSearchPattern(type)` = `RV.M.*` 등, 전체는 `RV.*`. `discoverListings({ type })` 는 노드가 넓게 돌려줘도 그 종류 글자로 다시 거른다. 데스크탑 장터의 종류 탭이 이 패턴을 쓴다.
- `RV.` 는 **관례 접두어일 뿐 우리가 소유하지 않는다.** 누구든 `RV.` 로 시작하는 루트를 만들 수 있다. 「RV. 로 시작하면 레이븐볼트 것」이라는 보장은 없다 — 신뢰는 §3 의 3층이 정한다.
- 하위 자산 모드: 접두어 상수를 `/` 로 끝나게 바꾸면(예: `RVSHOP/`) `RVSHOP/M.FOREST` 처럼 종류 글자 칸을 유지한 채 주인 표·100 RVN 규칙이 되살아난다(시험 있음).
- 소각액: 노드에 묻는 RPC 가 없어 화면은 늘 「체인과 대조: 확인 불가」. 대조 값이 들어왔는데 다르면 등록을 막는다(1단계 정책 유지).

이전에 비교한 안(기록): A `<접두어>.<작품>`(종류 칸 없는 루트) · B `<접두어>.<제작자>.<작품>`(가운데 칸은 신원이 아님 → 사칭에 쓰임) ·
C 제작자 루트 + 작품 하위(두 번째부터 소각 100 이라 보증 약화, 초보에게 어려움). 대표 확정안은 A 에 **종류 글자 칸**을 더한 모양이다.
B 모양(`RV.M.ALICE.SONG`)도 루트 이름 하나로 받지만 가운데 칸을 신원으로 쓰지 않는다.

### 2.1 충돌·사칭 경고 (`nameConflicts`, `nameSkeleton`, `suggestNames`)
- 정확히 같은 이름 = 체인이 막는다. 마법사 ③단계와 ⑦단계에 **「체인 중복 조회」 줄**이 있다(`name_taken` → 노드 `getassetdata`):
  「비어 있어요」/「이미 있어요」/「확인 불가」 + 「다시 조회」 단추. 확인 불가면 ⑦에서 등록 단추를 잠근다(정책 유지 — `planIssue` 의 `nameTaken: null` 차단).
- 비슷한 이름 = **경고**(막지 않음): 접두어·종류 글자·점·밑줄을 빼고 헷갈리는 글자(0→O, 1·L→I, 5→S, 8→B …)를 모은 뼈대가 같음 / 한 글자 차이 / 포함 / 같은 제목.
  종류 글자만 바꾼 같은 작품 이름(`RV.G.STAR_RUN` ↔ `RV.B.STAR_RUN`)도 「비슷한 이름」으로 경고한다(체인에서는 다른 이름이라 막히지 않음).
- 「공식」처럼 보이는 낱말(PLAYX·RAVENVAULT·RAVENCOIN·RAVI_STORY·OFFICIAL·VERIFIED·ADMIN·SUPPORT·레이븐볼트·공식)과 접두어를 겹친 작품 이름(`RV.M.RV.…`, `RV.M.RVN_…`) = 제작자 경고 + 구매자 화면 「공식 아님」.
- 구매자 목록은 서로 비슷한 항목 양쪽에 `lookalikes` 를 붙이고 상세 화면이 「사칭일 수 있으니 판매자 주소를 확인」을 보인다.
- 이름 자동 제안(`suggestNames(title, taken, { type })`): 고른 종류의 글자를 넣고(`RV.B.SEA_BOOK`), 제목이 한글뿐이거나 예약어면 종류별 영문 낱말(BOOK·SONG·TICKET…)로 제안하고, 이미 있는 이름은 `_2`, `_3` 으로 피한다.

## 3. 신뢰 3층 — 「누구나」 모델 (`core/creator/open-market.ts`, `listing.ts`)

| 층 | 조건 | 할 수 있는 것 | 못 하는 것 |
|---|---|---|---|
| 숨김 | 매니페스트 못 받음·깨짐·서명 틀림·남의 매니페스트(asset 칸 불일치)·**종류 글자 ≠ type**·**차단 목록** | — | 목록에 안 보임 |
| (a) 미검증 | 매니페스트 서명·형식 통과 | 정보·표지 보기, 외부 링크(`ipfs://…`) | 지갑 결제, 지갑 신원, 지갑 안 실행·재생 |
| (b) 보증 · 미검증 | (a) + 루트 자산(체인 규칙상 500 RVN 소각) + **자동 점검 통과**(모든 파일 받기·크기·SHA-256 일치·확장자/MIME/머리 재검사) + 선언 수수료율 = 지갑 요율 + 가격 ≤ 상한 1,000 RVN(초안) + 실행 코드가 아닌 종류 + (티켓) 행사 시작 전 + 대표가 정지하지 않음 | **결제 허용 + 경고 배지**, 미리듣기·미리보기(받은 바이트, 실행 없음) | 신원·세이브 연결, 게임 실행 |
| (c) 검증됨 | 대표 서명 허용 목록과 (자산·종류·매니페스트 CID·바이트 SHA-256·제작자·받는 주소) 정확 일치 | 결제, 신원·세이브, 게임은 지갑 안(샌드박스 iframe) | — |

- 소각은 **수익이 아니라 보증(스팸·사칭 비용)**이다. 문구 `BOND_SAY`: 「수수료가 아니에요… 아무도(레이븐볼트도) 받지 않아요… 판매자가 정직하다는 보장은 아니에요.」
- 구매 직전(`checkCreatorPurchase`)은 판정 결과를 믿지 않고 (b) 조건을 **다시 계산**한다. 요율은 매니페스트가 아니라 지갑 상수, 수수료 주소는 서명된 게임 등록부 값.
- (b)층 메모: gameIndex = 예약 번호 `OPEN_MARKET_GAME_INDEX = 0xfffe`(허용 목록은 0..0xfffd 로 줄였다), 아이템 번호 = `bondedItemId(asset)`(자산 이름 해시) — 같은 판매자의 다른 상품 구매와 섞이지 않는다(시험).

### 3.1 차단 목록 `rv-creator-denylist` v1
- 항목 `{kind: asset|creator, value, reason: scam|impersonation|malware|copyright|illegal|other, addedAt}`. creator 는 제작자 주소 또는 받는 주소가 같으면 그 사람의 모든 상품.
- 서명: 허용 목록과 같은 Ed25519 분리 서명·같은 키 목록, 도메인 `RAVENVAULT-CREATOR-DENYLIST-V1`. 허용 목록 서명을 차단 목록으로(또는 반대로) 쓸 수 없다(시험).
- 차단은 검증됨보다 앞선다. 내장 공개키 목록은 **비어 있다** → 출하 앱은 아직 아무 목록도 믿지 않는다(검증됨·차단 모두 없음).
- 신고 접수 경로·처리 기준·목록 배포 방법은 대표 결정(아래 §9).

### 3.2 (b)층이 안전한가 — 약점과 판단

**판단: 실행 코드가 아닌 종류(음악·책·티켓·디지털)에 한해 (b) 결제를 허용하고, 게임은 (b)에서 막는다.** 확신도: 중간. 이유와 약점:

| 위협 | (b)에서 막히나 | 설명 |
|---|---|---|
| 구매자 지갑 키 탈취(악성 게임 스크립트) | **막힘** | 게임은 (b)에서 지갑 안에서 실행되지 않는다(`runs-code` → 결제·실행 없음, 외부 링크만). 검증된 게임도 지갑과 다른 origin 의 `sandbox` iframe(웹 껍데기 CSP `connect-src 'none'`, `frame-src` = 그 게임 origin 하나, `frame-ancestors 'none'`)에서만 돈다 — 같은 출처 정책상 지갑 저장소·키에 닿지 못한다. 결제·신원은 postMessage 요청 → 지갑 **별도 창**에서 사람이 승인. 데스크탑은 게임을 기본 브라우저로 연다(키는 노드 안, 웹뷰 밖). 남는 위험: 게임 화면이 「복구 단어를 넣으세요」 같은 피싱을 띄우는 것 — 파일 검사의 `wallet-words` 경고는 일부만 잡는다 |
| 악성 PDF·EPUB | 일부 | 지갑은 PDF·EPUB 를 열지 않고 내려받기만 한다. 자동 점검이 `/JavaScript /OpenAction /Launch /EmbeddedFile`, EPUB 안 `<script>` 를 **경고**한다. 압축 스트림 속은 못 본다. 구매자 PDF 프로그램의 취약점은 우리가 막을 수 없다 |
| 제작자 사기(돈 받고 아무것도 안 줌·없는 행사 티켓) | **못 막음** | 비수탁이라 돈은 바로 제작자에게 간다. 막는 것: 가격 상한(1,000 RVN 초안), 경고 배지와 문구, 500 RVN 보증(사기 한 건당 비용), 차단 목록(사후). 환불은 제작자 책임이라는 문구 |
| 가짜 미리듣기·미리보기 | **못 막음** | 미리듣기 구간·미리보기 PDF 는 제작자가 고른다. 자동 점검은 「모양」만 본다 |
| 사칭(비슷한 이름·같은 제목) | 경고만 | 비슷한 이름 경고·「공식 아님」 표시·판매자 주소 표시. 같은 제목은 막지 않는다 |
| 바꿔치기(게이트웨이가 다른 파일을 줌) | **막힘** | 파일마다 SHA-256·크기 대조, 실패 시 (b) 아님 |
| 매니페스트 도용(남의 매니페스트 CID 를 내 자산에) | **막힘** | `asset` 칸 불일치 → 숨김 |
| 수수료 우회(선언 0%·출력 빼기·제작자 주소로 돌리기) | **막힘(우리 지갑 거래 안에서)** | 선언 ≠ 지갑 요율 → (b) 아님. 서명 직전 `inspectDirectPayment` 가 출력 정확 일치를 요구(빼기 `direct-pay-fee-output`, 합치기·돌리기 `direct-pay-company-output`). **제작자가 다른 길(직접 송금·카드)로 팔면 막을 수 없다** — 수수료는 우리 지갑이 만드는 구매 거래에서만 강제된다 |
| 파일이 공개됨 | 구조적 | IPFS 파일은 CID 를 알면 누구나 받는다. 구매 = 「소장 기록 + 판매자 응원」. 잠금(DRM·암호화 키 전달)은 서버 또는 판매자 상시 접속이 필요해 하지 않았다 |
| 보증이 너무 쌈 | 구조적 | 500 RVN(저장소 기재값)은 원화로 작다(설계 문서 가정 시세 기준 약 1,650원). 스팸 억지력은 약하다 → 가격 상한·차단 목록·검증 층이 함께 필요 |

게임을 (b)에서 막은 이유: 게임 결제는 게임이 구매자를 알아봐야(신원) 의미가 있는데 (b)는 신원을 주지 않는다. 그리고 실행 코드라 피싱 화면 위험이 가장 크다.
티켓을 (b)에 둔 것은 위험이 크다(없는 행사·큰 금액) — 가격 상한과 「재판매·환불·행사 취소 책임은 판매자」 문구에 기대고 있다. **티켓을 (b)에서 뺄지 대표 결정.**

## 4. 매니페스트 v2 — 열린 종류 (`core/creator/manifest.ts`, 종류 표 `limits.ts CONTENT_TYPES`)

v1(게임·음악 전용, `game`/`music` 칸)은 메인넷에 나간 적이 없어 받지 않는다. 서명 도메인 `RAVENVAULT-CREATOR-MANIFEST-V2`. 공통 칸은 1단계와 같고 종류별 칸은 `details` 하나에 둔다(모르는 칸·빠진 칸 거절).

| 종류 | `details` 필수 칸 | 파일 | 상한(초안) | (b) 결제 |
|---|---|---|---|---|
| game | entry(html), origin(https·ex.erci.se 금지·null), capabilities{identity,payment} | HTML·JS·CSS·그림·소리·글꼴·WASM·GLB | 파일 25MB·전체 200MB·2000개 | **안 됨**(실행 코드) |
| music | previewFile, previewStartMs, previewEndMs(1~60초) | MP3·M4A·OGG·OPUS·WAV·FLAC | 200MB·400MB·20개 | 됨 |
| book | bookFile, format(pdf·epub = 파일 확장자), previewFile(pdf·책 파일과 달라야·null), previewPages(1~50, 없으면 0), pageCount(null 가능, ≥ 미리보기) | PDF·EPUB | 100MB·150MB·3개 | 됨 |
| ticket | eventName, startsAt, endsAt(null·시작 뒤), venue, quantity(1~100,000), redemption{method: creator-signed-code, checkerAddress}, refundPolicy, contact | 포스터(선택, 그림·PDF) | 10MB·20MB·0~4개 | 됨(시작 전만) |
| digital | label(한 줄) | 그림·GIF·PDF·EPUB·TXT·소리 (HTML·JS·SVG·ZIP·실행 파일 안 됨) | 100MB·300MB·50개 | 됨 |

파일 검사 표(확장자↔MIME↔머리): 1단계 표 + `pdf`(`%PDF-`)·`epub`(ZIP 머리 + 30바이트 뒤 `mimetypeapplication/epub+zip`). 그냥 ZIP 은 받지 않는다(안을 볼 수 없음). 실행 파일 머리(MZ·ELF·Mach-O)를 이름만 바꾼 것은 「실행 파일」로 따로 말한다.
위험 무늬 경고(거절 아님): 1단계 6종 유지 + PDF 4종 + EPUB 2종. 화면은 늘 「자동 점검은 모양만 봐요」를 같이 보인다.

## 5. 티켓 사용(입장) 확인 — 서버 없이 (`core/creator/ticket.ts`)

1. 구매자가 지갑으로 산다(메모에 그 상품의 아이템 번호·구매자 주인 ID).
2. 판매자(또는 매니페스트 `checkerAddress`)가 체인에서 결제를 보고 **입장 코드**에 노드 signmessage 로 서명해 준다:
   `RAVENVAULT-TICKET-V1\n<자산>\n<구매 txid>\n<주인 ID>\n<좌석 번호>` → QR 글자 `RVT1.<base64url(정본 JSON)>`.
3. 행사장 기기가 **오프라인**으로 검사: 서명 주소 = checkerAddress, 같은 행사, 좌석 1..quantity, 시작 6시간 전~끝(끝이 없으면 시작+24시간), 이 기기에서 그 좌석을 이미 받았는지.

한계(문서·화면에 적음):
- 문이 여러 개면 「이미 사용」이 기기끼리 공유되지 않는다(한 기기로 받거나 목록을 손으로 합쳐야 함).
- 문 앞 검사는 「판매자가 이 코드를 내줬다」만 증명한다. 결제 확인은 판매자가 코드를 내주기 전에 해야 한다(지갑 구매 이력 도구는 아직 화면 없음).
- 코드를 캡처해 넘기면 먼저 온 사람이 쓴다(양도·재판매 통제 없음).
- 수량 초과 판매를 체인이 막지 않는다. 지갑은 읽은 판매 수로 「매진」을 알려 구매를 막을 뿐(`soldCount`), 동시 구매 경쟁은 못 막는다.
- 재판매·환불·행사 취소 책임은 판매자. 공연법·표 재판매 규제 등은 **전문가 확인 필요**.

## 6. 판매 대금과 수수료

- 수수료율 = `OPEN_MARKET_FEE_BPS` = 규약 v4 의 `DRAFT_PLATFORM_FEE_BPS`(1500 = 15%, 초안) **한 곳**. 상한 15%.
- 구매 거래 한 건 안에서 지갑이 나눈다: 출력 0 = 판매자 받는 주소(가격 − 수수료), 1 = 메모(0 sat), 2 = 수수료 주소(서명된 등록부), 3 = 잔돈. 시험: 300 RVN → 판매자 255 + 수수료 45, 수수료 주소에는 그 외 출력 없음, 판매자 = 수수료 주소면 거절, 수수료 주소가 없으면 판매 없음.
- 레이븐볼트는 돈을 맡지 않는다(비수탁). 기존 직접 결제 이력 읽기(`readDirectHistory`, 두 독립 출처)와 게임 원본 검증기가 그 거래를 `confirmed` 로 인정한다 → 기존 v4 구매 목록 형식과 같다(지갑 시험).
- 마법사 ③·⑤·⑦ 단계와 안내 화면에 늘 보이는 문구(`feeNotice`): 「판매될 때마다 15%(초안)가 레이븐볼트 수수료로 자동으로 나뉘고, 나머지는 내 받는 주소로 바로 들어와요」 + 「예: 300 RVN → 나 255 · 수수료 45」 + 내 가격 계산 + 「등록 때 내는 보증 500 RVN 과는 다른 돈」.
- **한계**: 수수료는 우리 지갑이 만드는 구매 거래에서만 강제된다. 제작자가 따로 직접 받는 판매(직접 송금·카드·다른 지갑)는 막을 수 없다. 대응은 검증 층 혜택과 체인 감사로 검증을 거두는 것뿐(설계 문서 §0-4).

## 10. 못 해 본 것 · 확신 낮은 부분

- 실제 노드 `signmessage` 출력과 매니페스트 서명 형식 대조(1단계와 같음), 실제 IPFS·`cid_alive`·`issue_asset` 호출(전부 모의).
- `listassets "RV.M.*"` 같은 종류별 검색을 실제 노드에서 돌려 보지 않았다(결과에 주인 표 `!`·하위 자산이 섞이는지, 노드 색인 필요 여부). 코드는 `!` 로 끝나는 이름을 숨기고 종류 글자로 다시 거른다.
- 메인넷에 이미 `RV.` 로 시작하는 자산이 있는지 조회하지 않았다(인터넷·노드 조회 안 함). 같은 이름이 이미 있으면 그 이름만 발행 불가 — 마법사 「체인 중복 조회」가 막는다.
- 예약어 목록(RVN·RAVEN·RAVENCOIN)은 데스크탑 create.rs 와 기억에 기댄 것 — Ravencoin assets.cpp 원본과 대조하지 않았다.
- 데스크탑의 장터 목록·IPFS 읽기 명령(Rust)과 구매 거래 연결 — 만들지 않았다. 폰 지갑(Expo) 장터 화면도 없다.
- 판매 현황(⑧)은 읽는 기능이 없어 「판매 없음」만 보인다.
- 네트워크 수수료는 추정 고정값 0.01 RVN(노드 견적 미사용).
- `nameSkeleton` 의 헷갈리는 글자 표·거리 기준은 근거 없는 초안 — 오경보·놓침이 있을 수 있다.
- PDF 위험 무늬는 압축 스트림 안을 못 본다. EPUB 은 ZIP 을 풀지 않는다.
- 전역 `button.ghost:hover` 가 밝은 테마에서 짙은 배경 + 짙은 글자가 되는 문제를 이 두 화면에서만 덮었다(다른 화면은 그대로 — 별도 확인 필요).
- 법률·세무 판단 없음.
