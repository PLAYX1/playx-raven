# 미니 창 (레이븐볼트 데스크탑)

대표 요청(2026-10-11): 「레이븐볼트 데스크탑을 애플 뮤직 미니 플레이어처럼 화면에 아주 작게 띄울 수
있으면 좋겠다. 크기별로 보여 주고, 입금이나 변화가 있으면 실시간으로 알려 줘.」

**미니 창은 읽기 전용이다.** 보내기·서명·복구 단어·비밀번호 입력은 미니 창에 없다(아래 「보안」).

## 1. 구조

| 파일 | 하는 일 |
|---|---|
| `src-tauri/src/mini_feed.rs` | 판단만(창·노드·OS 모름, 전부 시험): 거래 줄 → 입금 감지/확인/취소, 노드 흔들림 → 상태, 알림 묶기·속도 제한, **금액 가리기** |
| `src-tauri/src/mini.rs` | 창(라벨 `mini`) 만들기·보이기·숨기기·위치 기억, 설정(`mini-window.json`, 0600), 명령 5개, 문지기 `command_allowed`, 트레이 「미니 창」 묶음, OS 알림·메뉴막대 배지 |
| `src-tauri/src/mini_watch.rs` | 지켜보기 — 노드에 읽기 질문만, 15초 주기 |
| `src-tauri/capabilities/mini.json` | 미니 창 권한: 이벤트 듣기·창 끌기만 |
| `mini.html` · `src/mini-main.ts` · `src/mini-view.ts` · `src/mini.css` | 화면 |

기존 파일과 닿는 곳(최소 접점): `lib.rs`(mod 3줄·문지기 4줄·명령 5줄·`mini::setup` 1줄),
`ravi_companion.rs`(트레이 메뉴에 묶음 1개·메뉴 처리 1줄·`notify` 에서 주문 알림 넘기기 1줄),
`vite.config.ts`(입력 1개), `Cargo.toml`/`Cargo.lock`(notify-rust), `package.json`(스크립트 2줄).
`index.html`·`main.ts`·`styles.css`·`tauri.conf.json` 은 **안 건드렸다.**

열기: 트레이(메뉴막대) 아이콘 → 「미니 창」 → 열기 / 작게·보통·크게 / 항상 위에 / 금액 가리기.
마지막에 열려 있었으면 다음 실행 때 같은 자리·같은 크기로 다시 뜬다.

## 2. 크기

| 크기 | 창(논리 px) | 보이는 것 |
|---|---|---|
| S | 220×60 | 상태 점 + 총잔액(가림이면 `••••`) 또는 「새 소식 N」 + 크기·큰 화면·닫기 |
| M | 300×140 | 잔액 + 알림 띠 + 최근 변화 3건(입금·보냄·판매, 확인 수, 시각) + 노드 상태 |
| L | 360×260 | M + 들어오는 중 금액 + 지갑 잠김 여부 + 잠들지 않게 하는 중 + **판매자 모드일 때만** 오늘 판매·입금 요약 + 항상 위·소리·알림 칸 |

- 크기 바꾸기: 크기 단추, 창의 빈 곳 두 번 누르기, 트레이 메뉴. 순서 S→M→L→S.
- 끌어서 옮기기: 단추가 아닌 곳을 누르고 끈다(무테 창). 위치는 모니터 밖으로 못 나간다(모니터를 떼도 안쪽으로 당김).
- 닫기(×) = 트레이로 숨김. 앱 종료 아님.
- 잔액 글자를 누르면 가림 켬/끔.
- 테마: 운영체제 밝은/어두운 모드를 따른다. 모든 글자 대비 4.5:1 이상(시험으로 잼).

## 3. 알림

| 종류 | 언제 | 가림 켬(기본) 본문 | 가림 끔 본문 |
|---|---|---|---|
| 입금 감지 | 지갑에 들어온 거래를 처음 봄(0확인) | 「입금이 있어요.」 / 「입금 N건이 있어요.」 | 「12.5 RVN」 / 「12.5 RVN 외 2건」 |
| 입금 확인됨 | 확인 수가 기준(기본 1, 1~12)에 닿음 | 「입금이 확인됐어요.」 | 금액 |
| 판매 입금 감지/확인됨 | 주문 주소(`order`·`sell:`)로 들어온 돈 | 위와 같음 | 위와 같음 |
| 입금이 취소됐을 수 있어요 | 감지했던 입금의 확인 수가 음수(충돌) | 「큰 화면에서 확인해 주세요.」 | 금액 |
| 새 주문 | 판매자 모드에서 손님 주문(`ravi_companion::notify("order")`) | 「손님 주문이 들어왔어요.」 | 같음 |
| 노드가 답하지 않아요 | 지갑 질문이 두 번 연속 실패 | 「입금 감지가 멈췄어요…」 | 같음 |
| 인터넷 연결이 끊겼어요 | 연결 0곳이 두 번 연속 | 「0확인 입금은 믿지 마세요…」 | 같음 |
| 동기화가 멈췄어요 | 블록 높이가 15분 그대로(블록 1분 → 거짓 경보 확률 ≈ 3×10⁻⁷) | | |
| 노드가 다시 정상이에요 | 위 셋에서 회복 | | |
| 컴퓨터가 잠들 수 있어요 | 장사 모드·재색인인데 잠들기 막기를 못 함(`awake.rs`) | | |

- **켤 때 조용히**: 노드가 한 번이라도 정상으로 답하기 전의 「응답 없음」·「연결 0」은 알리지 않고 화면 상태로만 둔다(켤 때마다 경보 방지). 첫 정상은 「회복」으로 치지 않는다.
- **잠들었다 깸**: 노드 관찰 사이가 5분 넘게 비면 「멈춤」 시계를 다시 잰다(잠든 동안은 노드 잘못이 아니다).
- **어디로**: 미니 창이 보이면 창 안 띠(12초, 누르면 「봤음」). 안 보이면 OS 알림(맥·윈도우). 둘 다 메뉴막대 배지(맥: 아이콘 옆 숫자, 윈도우: 툴팁).
  미니 창과 OS 알림을 동시에 내지 않는다(겹침 방지). 라비 작은 창(기존)의 입금 방문은 그대로다.
- **묶기**: 한 바퀴(15초)에 생긴 일은 한 장. OS 알림은 **60초에 한 장까지**, 그 사이 일은 다음 장에 「다른 소식 N건」으로 묶인다. 대기 상한 200개.
  가장 급한 종류가 제목(취소 > 노드 이상 > 확인됨 > 감지 > 주문 > 회복).
- **가림**: 기본 켬. 켜져 있으면 금액·자산 이름이 **Rust 밖으로 안 나간다** — 창도 OS 알림도 가려진 글만 받는다(잠금 화면 알림 보호).
  주소·txid 는 가림과 상관없이 창으로 보내지 않는다.
- **소리**: 기본 끔. 켜면 OS 알림 소리(맥 Ping, 윈도우 Default) / 미니 창 안 짧은 삑.
- **OS 알림 구현**: `notify-rust` 4.x 를 Rust 에서 직접 부른다. `tauri-plugin-notification` 은 검토 후 **안 씀**:
  ① 최신(2.5.1)은 tauri 를 2.11→2.12 로 끌어올려 Cargo.lock 이 크게 바뀌고(wry·tao·muda 등), ② 2.3.3 도 모든 창에 JS(`window.Notification` 덮어쓰기)를 심고 IPC 명령 3개를 연다.
  직접 쓰면 새 IPC·새 권한 0개, Cargo.lock 은 새 크레이트 추가만(기존 판 변경 0). 리눅스는 dbus(zbus) 를 끌고 오므로 제외 → 트레이·미니 창만.

## 4. 실시간성 — 실제 지연

**감지 방식은 노드 RPC 폴링이다.** ZMQ·`-walletnotify` 는 쓰지 않는다(아래 「제안」).

| 지켜보는 것 | 주기 | 지연 |
|---|---|---|
| 큰 창 지갑감시(기존 `main.ts`, `wallet_since`) | 15초 | 0~15초. 🔴 웹뷰 타이머라 창을 숨기면 OS 가 늦추거나 멈출 수 있다 |
| 라비 작은 창(기존) | 따로 안 묻는다 — 위 결과에 얹혀 감(`observe_rpc`) | 위와 같음 |
| **미니 창 지켜보기(신규, Rust)** | 15초(`listsinceblock` 마지막 지점 이후만) | **0~15초, 평균 7.5초** + RPC 약 20ms |
| 잔액·잠금 | 60초, 지갑 변화가 있으면 즉시 | |
| 노드 높이·연결 | 60초 | 응답 없음 15~30초 · 연결 끊김 60~120초 · 멈춤 15~16분 |
| OS 알림 | 첫 장 즉시, 이후 60초에 한 장 | |

**실측(regtest, `npm run check:mini-regtest`, `artifacts/claude-mini/regtest-latency.json`)** — Raven Core 4.8.0, 임시 폴더·밖과 연결 없음:
- 0확인 입금 감지 3회: 6.1초·14.7초·6.0초(각각 다음 질문까지 남은 시간 + 약 20ms). 모두 첫 질문에서 잡힘.
- `listsinceblock(cursor, need=3, true)` 는 같은 입금을 확인 0→1→2→3 까지 **매번 다시 돌려주고**, 3을 넘으면 더는 안 돌려준다 → 「입금 확인됨」 판정의 근거 확인, 그 뒤 질문 부담 없음.
- 🔴 **지갑을 암호화·잠근 상태에서도 입금이 감지됐다**(`unlocked_until=0`, 감지 3/3, 잔액도 읽힘). 잠금은 서명(쓰기)만 막는다.

실제 메인넷 노드에서의 전파 지연(보낸 사람 → 우리 노드 mempool)은 재지 않았다. 보통 수 초지만 연결 수·네트워크에 따라 다르다.

**지연을 줄이는 길(제안, 아직 안 함):**
1. 미니 창이 **보일 때만** 주기를 5초로(안 보이면 15초). 질문은 마지막 지점 이후만 오므로 노드 부담은 작다(질문 1개/5초, 응답은 새 줄만). 배터리: 노트북에서 5초 깨움은 15초보다 약간 더 쓴다 — 측정 안 함. 하한은 5초를 권함(노드 RPC 스레드 4개를 다른 화면과 나눠 씀).
2. 노드 이벤트: `-zmqpubhashtx`·`-walletnotify=<명령>` 으로 즉시(1초 미만). 단 노드 설정(`raven.conf`)을 바꿔야 하고 노드 재시작이 필요하며, `walletnotify` 는 셸 명령 실행이라 보안 검토가 필요하다. 대표 결정 항목.

## 5. 권한·보안

- **IPC 문지기**: `lib.rs` invoke_handler 가 명령을 처리하기 **전에** `mini::command_allowed(창 라벨, 명령)` 을 본다. 라벨 `mini` 는 `mini_state`·`mini_set`·`mini_show`·`mini_open_main`·`mini_seen` 다섯만 통과. `send_rvn`·`unlock_for`·`reveal_seed`·`words_restore_*`·`sales_account_reveal`·`wallet_balance` 등은 거절(시험 `mini_window_can_only_reach_read_only_commands`).
  미니 창은 잔액을 직접 묻지도 못한다 — Rust 가 가림 규칙을 거친 한 장(`mini-snapshot`)만 보낸다.
- **capability** `mini.json`: `core:event:allow-listen`·`allow-unlisten`·`core:window:allow-start-dragging` 셋뿐. opener·dialog·process·updater·notification 없음. 기존 `default.json`(main)·`companion.json` 에 `mini` 없음(시험).
- `mini_set` 은 모르는 칸을 거절(`deny_unknown_fields`) — 위치·열림 같은 값은 창 이벤트만 바꾼다.
- **화면 캡처 보호** 기본 켬(`content_protected`): 화면 공유·스크린샷에 미니 창이 빈칸으로 나온다(맥 `NSWindowSharingNone`, 윈도우 `WDA_EXCLUDEFROMCAPTURE`). 끄는 단추는 아직 화면에 없다(설정 파일·`mini_set` 으로만) — 대표 결정 항목.
- **잠금 상태 표시**: L 에 「지갑 잠김 · 감지는 계속」/「지갑 열림」/「지갑 암호 없음」.
- **CSP 그대로**: `tauri.conf.json` 안 바꿈. 미니 화면은 `style=""` 속성을 쓰지 않는다(Tauri nonce CSP 에서 무시됨 — 시험이 0개 확인).
- 설정 파일 `mini-window.json` 은 0600, 2KB 넘거나 모르는 칸이 있으면 기본값으로.
- 지켜보기는 미니 창이 보이거나, **미니 창을 한 번이라도 연 사람**이 OS 알림을 켜 두었을 때만 노드에 묻는다. 안 써 본 사람의 노드에는 질문이 늘지 않는다.

## 7. 한계 — 앱을 실제로 띄워 확인하지 못한 것

다음은 **코드와 문서로만** 맞췄고, 실제 맥·윈도우에서 앱을 띄워 보지 않았다:
- 무테 창 끌기(`startDragging`)·항상 위·작업 표시줄 숨김·`content_protected` 가 각 OS 에서 실제로 그렇게 보이는지.
- OS 알림이 실제로 뜨는지, 알림 권한 묻기가 뜨는지. 맥 `notify-rust`(기본 NSUserNotificationCenter, 옛 API)는 서명된 앱 묶음의 식별자로 보낸다 — 개발 실행(`tauri dev`)에서는 「터미널」 이름으로 뜬다. 맥 새 버전에서 옛 API 가 조용히 안 뜰 가능성이 있다(확신 낮음). 안 뜨면 미니 창·배지는 남는다.
- 윈도우 알림은 설치본에서만 앱 이름(AppUserModelID)으로 뜬다. 개발 실행은 PowerShell 이름.
- 맥 메뉴막대 숫자 배지(`tray.set_title`)의 실제 모양.
- 맥에서 미니 창이 다른 앱의 전체 화면 공간 위에 뜨는지(항상 위의 OS 제약).
- 배터리 영향(15초 주기) 측정.

그 밖의 한계:
- 노드 지갑이 아는 주소만 감지한다. 브라우저 쪽 열쇠(웹 지갑·폰)로만 받는 주소는 이 노드 지갑에 없으면 안 보인다.
- 0확인 입금은 되돌려질 수 있다 — 그래서 「입금 감지」와 「입금 확인됨」을 나눴다. 「확인됨」 기준은 기본 1회.
- 판매자 「오늘 요약」은 기준선(약 1,600블록 ≈ 하루+) 안의 지갑 줄만 센다. 1,600블록보다 오래 앱을 안 켰다 켜면 그 사이 줄은 요약에 안 들어간다.
- 리눅스: OS 알림 없음(트레이·미니 창만), 웨이랜드에서는 위치 옮기기 제약.
- 말: 한국어·영어만(일·중은 영어로).

## 8. 대표 결정이 필요한 것

1. OS 알림을 **미니 창을 한 번도 안 연 사람에게도** 켤까? (지금: 한 번 연 사람만)
