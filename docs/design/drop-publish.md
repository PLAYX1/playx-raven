# 끌어놓기 발행 — 「내 게임·음악·책·티켓 올리기」를 한 화면으로

대표 요청(2026-10-11): 「그냥 드래그 드롭으로 바로 작동하거나 클릭으로도 작동하거나, 템플릿으로 쉽게 꾸미거나, 애플 프로그램처럼 쉽게 작동했으면 좋겠다.」
추가(같은 날): 「글씨가 밀리고 칸이 좁고 그런 디자인 없이, 카카오톡처럼 잘 디자인되어야 한다.」

브랜치 `claude/rv-drop-publish`(기준 `87116a5` — 9단계 마법사·`RV.<종류>.<이름>`). 기존 마법사는 「자세히(단계별로)」로 그대로 남는다.

## 0. 한눈에

| | 전(9단계 마법사) | 후(끌어놓기 발행) |
|---|---|---|
| 주 작업 1회 탭 수(코드 실측) | 안내 체크 1 + 시작 1 + 종류 1 + 다음 7 + 파일 1 + 새 주소 1 + 올리기 1 + 이름 다시 적기(타이핑) + 등록 1 = **14탭 + 타이핑 2칸(제목·이름 2번)** | **놓기(1동작) + 「발행」 1 + 「발행하기」 1 = 2탭, 타이핑 0** |
| 화면 전환 | 9번 | 0번(확인 창 1겹) |
| 첫 폴드 선택지 | 단계마다 다름 | 3개: 놓기/고르기 · 폴더 고르기 · IPFS 주소 |
| 자동으로 정하는 것 | 없음(사람이 다 고름) | 종류·형식(싱글/EP/앨범)·제목·이름·표지·여는 파일·책 미리보기·가격 기본값·템플릿·받는 주소·안전한 파일 이름 |

자동으로 정한 것은 숨기지 않는다 — 카드에 그대로 보이고(「음악 · EP」, 이름, 가격), 「고급」에서 바꾼다(playx-simplicity §4 「묻지 않되 말해 준다」).

## 1. 사용 시나리오

1. **초보 판매자** — 그림 몇 장을 끌어다 놓는다 → 「그림을 어떻게 팔까요?」(그림 모음 / 행사 티켓) 한 번만 묻는다 → 카드 미리보기 → 「발행」 → 확인 창 → 끝. 파일 이름이 한글·빈칸이어도 자동으로 안전한 이름으로 바꾸고(「이름을 바꿨어요」 한 줄), 원래 이름은 제목·곡명에 쓴다.
2. **어르신** — 큰 놓기 칸(220px 이상, 글자 1.25rem)과 단추 하나. 모르는 것을 묻는 일은 한 번뿐이고, 막히면 「지금은 발행할 수 없어요: 원인 → 다음 행동」 한 줄. 되돌릴 수 없는 일은 확인 창에 한 번 모아서.
3. **뮤지션** — 앨범 폴더(곡 7개 + cover.jpg)를 놓는다 → 앨범으로 보고 앞 번호 순서(자연 정렬)로 곡 목록, 「01 - 숲의 노래.mp3」 → 곡명 「숲의 노래」, 표지 자동, 미리듣기는 첫 곡 30초(곡 길이를 읽으면 30~60초 지점). 「고급 → 곡 순서·곡명」에서 ↑↓로 바꾸고, 싱글/EP/앨범을 고친다.
4. **게임 개발자** — 빌드 폴더를 놓는다 → index.html(가장 얕은 것)을 여는 파일로, 안의 그림은 게임 파일로 두고 갤러리에 쓴다. 「코드를 실행해요」 주의 칩이 항상 붙고, 기본 가격은 무료(검증 전 게임은 지갑 결제 불가).
5. **가게 사장** — 「가게 메뉴형」 템플릿으로 가게 소개를 미리 본다. 🔴 `RV.S.`(가게) 종류 글자는 아직 대표 확정 전이라 **미리보기 전용**(발행 없음) — §9 결정 1.

## 2. 상태 머신

```
          drop/pick/paste            detected
  idle ───────────────▶ detecting ───────────▶ preview ◀────────┐
   ▲                        │ unsure               │ publish     │ cancel / Esc
   │                        ▼                      ▼             │
   │                       ask ──answer──▶ preview  confirm ─────┘
   │                                               │ confirm
   │  reset                         blocked ◀──────┤ (점검이 막으면 언제든)
   │                               (unblocked→preview)
   │                                               ▼
   └──────────── done ◀──issued── publishing ──failed──▶ preview(이어하기: 올린 파일은 CID 캐시로 건너뜀)
```

- 정의: `src/drop-state.ts` `DROP_TRANSITIONS`(받지 않는 사건은 무시). 시험: `scripts/drop-publish.test.mjs` 「state machine」.
- **발행 중(publishing)·확인 창(confirm)에서는 새로 놓은 것을 받지 않는다**(올리던 것을 덮지 않는다). 오버레이도 그때는 안 뜬다.
- 이어하기: 초안(`rv-drop-draft-v1`, 공개 정보만 — 칸 값·꾸밈·곡 순서·파일 SHA-256·CID 캐시)이 자동 저장된다. 다시 열면 「지난번 올리던 ○○이 있어요 — 같은 파일을 다시 놓으면 칸을 이어서 채우고, 이미 올린 파일은 건너뛰어요」. 파일을 다 올리고 발행만 남은 경우는 파일 없이 바로 발행으로 이어진다. 파일 바이트·비밀번호·시드는 저장하지 않는다.

## 3. 화면 명세(한 화면 + 단추 하나)

위에서 아래로(폭 상한 880px, 좁으면 그대로 1열):

1. 머리줄: 「내 상품 올리기」 · [자세히(단계별로)] [닫기] · 「시험 단계 — 실제 메인넷 발행은 꺼져 있어요」
2. **빈 화면(idle)**: 큰 놓기 칸(단추 — 누르면 파일 고르기) · [파일 고르기] [폴더 고르기] · 「IPFS 주소 붙여넣기」 칸 + [불러오기]. 입력칸 밖에서 ⌘V 로 `ipfs://…`나 파일을 붙여 넣어도 받는다.
3. **창 전체 드롭 오버레이**: 파일을 끌고 들어오는 순간 「여기에 놓으면 상품이 만들어져요 / 놓기만 하세요. 종류·이름·표지는 알아서 채워요」. 데스크탑은 main.ts 의 `drop-enter`(Tauri) → `dropJob()` 의 `creator` 칸이 같은 문구를 쓴다.
4. **묻기(ask)**: 모를 때만, 가능한 종류만 보기로(큰 단추).
5. **미리보기(preview/blocked)**: 「구매자는 이렇게 봐요」 + **실제 판매 페이지 카드**(구매자 화면과 같은 `renderStorefront`) → 꾸미기 줄(모양·색, 펼치지 않아도 보임) → 자동 점검 칩(통과/주의/막힘 + 쉬운 이유 + 다음 행동) → **비용 한 줄**(「등록할 때 한 번: 보증(소각) 500 RVN + 네트워크 수수료 약 0.01 RVN · 팔릴 때: 수수료 15%(초안)」 — 서명된 수수료 일정이 주입되면 그 요율·출처) → **[발행]** → 막혔으면 이유 한 줄 → 「고급」(접힘).
6. 「고급」(점진 공개): 종류 · 제목 · 한 줄 소개 · 설명 · 태그 · 가격 · 상품 등록증 이름(고정 앞부분 `RV.M.` + 작품 이름 + 제안 3개) · 받는 주소(+새 주소) · 표지 끌어놓기/고르기 · 음악: 싱글/EP/앨범, 곡 순서 ↑↓·곡명, 미리듣기 구간 · 책: 쪽수·미리보기 쪽수 · 티켓: 행사·시작·끝·장소·수량·환불·연락처 · 디지털: 상품 종류 한 줄 · 바꾼 파일 이름/넣지 않은 파일과 이유.
7. **확인 창**(되돌릴 수 없다는 한 번): 이름 크게 + 비용 3줄 + core `planIssue().irreversible` 5줄 그대로. 포커스는 [취소]에서 시작, Esc = 취소.
8. **발행 중**: 진행률 막대 + 「2/5 · cover.png」 + 「닫아도 다음에 이어서 할 수 있어요」.
9. **완료**: ✓ 「발행했어요」(포커스 이동) · 장터에서 찾을 이름 · 거래 번호 · 알림 글 복사 · [다른 것 올리기]. 「내 상품」 목록(`rv-creator-mine-v1`)은 마법사와 공유.

## 4. 자동 종류 추정(`src/drop-detect.ts`)

| PDF·EPUB 만(+그림) | 책 | EPUB 이 본문. PDF 둘이면 preview/sample/미리/맛보기 이름 또는 작은 쪽이 미리보기 |
| 글(.txt)만 | 디지털 | |
| 그림만 | **한 번 묻기**: 그림 모음 / 티켓 포스터 | |
| 섞임 | **한 번 묻기**: 담을 수 있는 종류만 | 하나도 없으면 「종류별로 나눠서 놓아 주세요」 |
| exe·zip·dmg·모르는 확장자, 확장자를 속인 실행 파일 | 넣지 않음 + 이유 | `.DS_Store`·`__MACOSX`·`Thumbs.db` 는 조용히 뺀다 |

## 5. 끌어놓기가 실제로 어떻게 들어오나(Tauri) — 근거

- 메인 창은 `tauri.conf.json` 의 창 설정(`create: false`)을 `ravi_companion.rs::open_main` 이 `WebviewWindowBuilder::from_config` 로 만든다. `dragDropEnabled` 를 따로 끄지 않으므로 **기본값 = 켜짐** — Tauri 가 OS 드롭을 가로챈다(`node_modules/@tauri-apps/api/webview.d.ts` 451–454: 「Whether the drag and drop is enabled or not on the webview. By default it is enabled. Disabling it is required to use HTML5 drag and drop on the frontend on Windows.」).
- 가로챈 드롭은 `ravi_companion.rs` 562–575 의 `WindowEvent::DragDrop` → `drop-enter`·`drop-files {paths}`·`drop-leave` 이벤트로 화면에 온다. **경로(절대 경로 문자열, 폴더는 폴더 경로 그대로)** 만 오고 내용은 없다. 그래서 `onDragDropEvent`(JS) 대신 이미 있는 이 러스트 이벤트를 쓴다 — 같은 정보이고, 「방금 떨어뜨린 목록」(`dropbox.rs remember`)이 이 길에서만 채워지기 때문이다.
- 내용은 새 러스트 명령이 읽는다(`src-tauri/src/drop_publish.rs`): `creator_dropped_list(path)`(폴더면 하위 파일 목록, 깊이 8·2000개 상한, 바로가기 안 따라감, 숨김·OS 찌꺼기 제외), `creator_dropped_read(root, rel)`(**떨어뜨린 경로와 그 안만**, `..`·절대·`\`·`:` 거절, 정규화 후 폴더 밖이면 거절, 200MB 상한), `creator_cid_read(cid)`(이 컴퓨터 IPFS `cat`, 25MB 상한). 러스트 시험 3개 통과(`cargo test --lib drop_publish`).
- **HTML5 드롭**(`DataTransfer`, 폴더는 `webkitGetAsEntry`)도 같은 결과로 처리한다 — 브라우저 하네스, 그리고 창의 드롭 가로채기를 끄는 경우(윈도우 등)를 위해.
- 🔴 **확인 필요(못 해 본 것)**: 실제 macOS·Windows 에서 Finder/탐색기 드롭(특히 Tauri 가로채기가 켜진 상태에서 HTML5 `drop` 이 웹뷰에 오지 않는지, 폴더 경로가 그대로 오는지)은 실제 앱으로 확인하지 못했다. 하네스는 `drop-files` 이벤트를 흉내 낸다. 확신: 중간.
- 발견(기존 버그 가능성, 확신 중간): 기준 브랜치의 마법사 ② 단계 놓기 칸(`#cw-drop`)은 HTML5 `drop` 만 듣는다. 데스크탑에서는 Tauri 가 가로채므로 그 칸에 놓아도 `onDropped` 의 「여기서는 받지 않습니다」로 갈 가능성이 높다. 이번 변경으로 `creator` 화면의 드롭은 끌어놓기 발행으로 간다(마법사 모드일 때는 「끌어놓기 화면으로」 안내).

## 7. 템플릿·꾸미기(`src/drop-look.ts`)

- 모양 7종: 음악 앨범 표지형(`album`) · 싱글 한 곡형(`single`) · 책 표지형(`book`) · 스크린샷 갤러리형(`gallery`, 게임·디지털) · 행사 카드형(`event`) · 가게 메뉴형(`shop`, 미리보기 전용) · 간단 기본형(`basic`, 모든 종류).
- 색 7종: 앱 색 따라가기(라이트·다크) · 종이 · 밤 · 숲 · 노을 · 바다 · 흑백. 고정 6색은 본문·흐린 글·강조·강조 위 글 **모든 짝이 4.5:1 이상**(시험).
- **사용자는 값만 고른다.** 임의 HTML·CSS·JS 없음. 글은 전부 `textContent`. 그림 주소는 `blob:`·`data:image/(png|jpeg|webp|gif)`·`http://127.0.0.1:8080/ipfs/Qm…`만(SVG data 는 스크립트를 품을 수 있어 제외). 시험: `<script>`·`onerror`·`javascript:` 를 넣어도 실행·적용 0.
- **신뢰 띠**: 템플릿 바깥, 카드 맨 위, 테마와 상관없는 고정 색(#fdeccc/#4a2a00). 「보증 · 미검증」 + 「레이븐볼트가 검토하지 않은 판매자…」 + (해당 시) 「공식 상품이 아니에요」·「비슷한 이름이 있어요」. 7×7 = 49 조합 전부에서 첫 자식·보임·본문 위·4.5:1 이상(시험).
- 꾸밈 데이터(검증 가능한 안전한 칸): `{ template, theme, tagline(≤80), coverImage, background, gallery[≤8] }` (태그는 찾기용이라 장르 칸 §15 로 옮겼다) — 그림은 **경로**로만 가리키고, 경로는 매니페스트의 files/cover/look.images 항목(CID·SHA-256·크기·MIME)이어야 한다. `validateLook` 은 모르는 칸·양방향 덮어쓰기 문자(U+202A–202E, 2066–2069)·종류에 맞지 않는 템플릿을 거절한다.

## 8. 매니페스트 확장 v3(제안 — `src/drop-manifest.ts`, 스위치 꺼짐)

```
v3 = v2 의 모든 칸(검사도 v2 검사기 그대로) + 세 칸
  look : { template, theme, tagline, coverImage, background, gallery[], images: FileEntry[≤8] } | null
  genre: { main: 종류별 고정 장르 id | null, tags: 자유 태그 ≤3(각 ≤20자) } | null      (§15)
  music: { format: 'single'|'ep'|'album', tracks: [{ title, file, durationMs|null, preview{startMs,endMs}|null }] } | null   (type=music 이면 필수)
서명 도메인 RAVENVAULT-CREATOR-MANIFEST-V3 (v2 서명과 섞이지 않음)
```

- 곡 수: 싱글 1–3 · EP 2–6 · 앨범 4–20. 모든 소리 파일이 tracks 에 정확히 한 번(순서 = 앨범 순서). v2 `details.previewFile/Start/End` = 미리듣기가 있는 첫 곡과 같아야 함(v2 만 읽는 지갑도 같은 미리듣기를 쓴다). 미리듣기가 곡 끝을 넘으면 거절.
- `readManifestAny` 는 v2·v3 둘 다 읽는다. `toV2Unsigned` 는 꾸밈·곡 목록을 뺀 v2 로 내린다(다시 서명 필요).
- 🔴 **지금은 v2 로만 발행한다**(`DROP_MANIFEST_V3_ENABLED = false`). 이유: 오늘의 v2 검사기(vendored core, 시험으로 확인)는 v3 를 거절한다 — v3 를 체인에 올리면 구매자 화면에서 「형식 오류」가 된다. 그래서 꾸밈·곡 목록은 판매자 미리보기와 초안에만 있고, 화면이 「구매자 지갑이 새 상품 정보(v3)를 읽게 된 뒤에 함께 실려요」라고 말한다.
- **양쪽 vendor SHA 규칙**: core/creator/* 는 지갑 저장소(`ravenvault` `core/creator`)가 원본이고 데스크탑은 바이트 복사본(`core/creator/vendor-sha256.json` 고정, `scripts/creator-publish.test.mjs` 가 대조). v3 를 켜는 순서:
  1. 지갑 저장소 `core/creator/manifest.ts` 에 v3 검사(이 파일의 `validateManifestV3`·`verifyManifestV3`·`readManifestAny` 그대로)와 `drop-look.ts` 의 `validateLook`·`safeText` 를 옮기고 지갑 쪽 시험을 돌린다.
  2. 구매자 화면(open-market)이 v3 를 읽어 `renderStorefront` 로 그리게 한다(신뢰 띠 포함).
  3. 지갑 저장소 `vendor-sha256.json`(있다면)과 데스크탑 `core/creator/vendor-sha256.json` 을 **같은 커밋 기준으로** 갱신하고 파일을 복사한다. 데스크탑에서 core 를 직접 고치지 않는다.
  4. 데스크탑 `src/drop-manifest.ts` 의 중복 구현을 core import 로 바꾸고 `DROP_MANIFEST_V3_ENABLED` 를 켠다(대표·지갑 담당 결정).
- 알려진 비용: v3 경로(`publishV3`)는 core `publishContent` 를 재사용하느라 서명을 두 번 한다(v2 중간본 — 보관하지 않음 — + v3). 지갑이 잠겨 있으면 비밀번호를 두 번 물을 수 있다. 3단계에서 core 로 옮길 때 한 번으로 줄인다.

## 9. 대표가 고를 것

1. **가게 종류 글자 `RV.S.`** — 지금 표(`ASSET_KIND_LETTER`)에 없다(M·G·B·T·X). 가게 메뉴형 템플릿은 미리보기 전용. 「가게」를 상품 종류로 둘지(체인에 가게 소개 자산을 500 RVN 으로 만드는 것), 아니면 가게 소개는 체인 밖(서명된 가게 문서)으로 둘지.
2. **확인 방식** — 지금: 확인 창 한 번(이름을 크게 보이고 되돌릴 수 없는 5줄). 마법사의 「이름 똑같이 다시 적기」는 끌어놓기 화면에서는 뺐다(요청: 「확인은 되돌릴 수 없다는 한 번만」). 메인넷을 켤 때 다시 적기를 되살릴지.
3. **가격 기본값(초안)** — 싱글 5 · EP 15 · 앨범 30 · 책 20 · 티켓 30 · 디지털 10 RVN · 게임 0. 「제안」으로 카드에 보이고 고급에서 바꾼다. 기본을 「무료」로 할지.
4. **다른 화면에 놓았을 때** — 지금: 판매자 기능이 켜져 있고 그 화면에 정해진 뜻(자산·이야기·가게·만들기)이 없으면 「이 파일로 상품을 만들까요?」 한 번 묻고 끌어놓기 발행으로. 문서(PDF 등)는 기존대로 증명서 질문이 먼저다. 「앱 어디서나 바로 상품」으로 더 넓힐지(돈이 드는 일과 겹칠 위험 — main.ts 주석 「떨어뜨린 자리가 곧 뜻이다」).
5. **v3 켜는 시점·주체**(§8).
6. **de·ru 문구** — 레이아웃 시험용 초안(번역가 검수 전). 앱 언어 목록(ko·en·ja·zh)에 de·ru 를 넣을 때 함께 검수.
7. **영상 종류 글자 `V`**(`RV.V.<이름>`) 와 허용 도메인 목록(§14).
8. **장르 목록**(§15) — 종류별 고정 id 는 장터 필터 키라 한 번 정하면 바꾸지 않는다(보이는 말만 고침). 목록 확정.

## 10. 접근성

- 전부 키보드로 된다(시험: 붙여넣기 칸 → Enter → 묻기 → 고급 펼치기 → 종류 바꾸기 → 모양·색 고르기 → 발행 → Esc 로 취소 → 다시 → Tab → Enter → 완료, 포커스가 결과로 이동). 고른 단추에 포커스가 남는다.

- 사용자 글(제목·곡명·장소·메뉴)은 `translate="no"`(앱 i18n 규칙).

## 13. 위험

- 실제 OS 드롭·실제 IPFS(`creator_cid_read`·kubo)·실제 노드는 시험하지 않았다(모의 어댑터·하네스만). 메인넷 발행은 꺼진 채.
- 큰 파일: 놓은 파일을 base64 로 IPC 에 실어 화면 메모리에 올린다(마법사 `ipfs_add_file` 도 같은 방식). 수백 MB 앨범·게임은 느리거나 메모리가 부족할 수 있다 — 러스트가 경로로 바로 보관하는 길(`ipfs_add_dropped` 처럼)로 바꾸는 것이 다음 개선.
- 자동 추정이 틀릴 수 있다(예: 소리 파일이 든 그림 모음). 카드에 판정이 보이고 고급에서 바꾼다.
- 곡 길이는 브라우저가 읽을 수 있을 때만(못 읽으면 0~30초 기본).
- 가격 기본값이 있는 상태로 발행될 수 있다 — 카드와 확인 창에 가격이 보인다(§9 결정 3).
- `RV.S.` 미정, v3 꺼짐 → 꾸밈은 아직 구매자에게 안 보인다(화면이 그렇게 말한다).

## 14. 영상 종류(제안 — `RV.V.<이름>`, 대표 확인 대기)

대표 결정(이전): 영상은 파일을 올리지 않고 **Vimeo 등 링크를 넣어 앱 안에서 재생**한다. 이번 브랜치는 **설계만** 했다(구현 없음) — 종류 글자 표(`ASSET_KIND_LETTER`)·`CONTENT_TYPES`·매니페스트 검사가 전부 지갑 저장소 core 에 있어서, §8 과 같은 순서(지갑 저장소 먼저 → vendor SHA 갱신 → 데스크탑)로 들어가야 한다.

| 항목 | 설계 |
|---|---|
| 이름 | `RV.V.<작품이름>` — `V` 는 **제안**(지금 `X` 처럼 `KIND_LETTER_PENDING` 에 넣고 대표 확인 후 확정) |
| 파일 | 없음(minFiles 0). 표지 그림만 선택 |
| details | `{ videoUrl, trailerUrl \| null, provider, durationSec \| null }` — `videoUrl` 은 구매자 전용 본편, `trailerUrl` 은 **무료 예고편 별도 칸**(구매 전 누구나 재생) |
| 허용 도메인 | 고정 목록만: `player.vimeo.com`·`vimeo.com`(→ 플레이어 주소로 바꿔 저장)·`www.youtube.com`·`youtu.be`·`www.youtube-nocookie.com`. https 만, 쿼리는 허용 목록 키(예: Vimeo `h=` 비공개 해시)만 남김, 그 밖의 주소는 거절. 데스크탑 CSP `frame-src` 가 이미 `https://www.youtube.com https://player.vimeo.com` 만 허용 — 같은 목록 |
| 재생 | **격리 임베드**: `<iframe sandbox="allow-scripts allow-same-origin allow-presentation" referrerpolicy="no-referrer" allow="fullscreen; picture-in-picture">`, 지갑 화면과 postMessage 없음(main.ts `videoEmbed` 와 같은 방식). 영상 페이지는 지갑 기능에 닿지 못한다 |
| 장르 | 강의 · 운동 · 영화·단편 · 다큐 · 어린이 · 뮤직비디오 · 그 밖의 영상(`drop-genre.ts GENRES.video`, 이미 표에 있음) |
| 수수료 | 다른 종류와 같은 기본(수수료 규약 v4, 지금 초안 15%) |
| 끌어놓기 발행 | **링크 붙여넣기 한 칸으로 끝**: 붙여넣기 칸(또는 ⌘V)에 Vimeo/YouTube 주소 → 종류 「영상」 자동 → 제목은 링크의 공개 정보(oEmbed)를 쓰지 **않고**(외부 호출 금지 원칙) 사람이 고급에서 적거나 「My Video」 기본 → 카드에 예고편 자리 → [발행]. 영상 파일(mp4 등)을 놓으면 「영상 파일 대신 영상 주소를 붙여넣어 주세요」(main.ts 기존 문구와 같음) |
| 🔴 한계(구매 화면에 늘 안내) | ① **접근 통제는 판매자 호스트(Vimeo 등)의 몫**이다 — 링크를 아는 사람은 구매 없이 볼 수 있다(Vimeo 비공개 링크·도메인 제한으로 판매자가 막아야 함). ② 판매자는 **구매 후에도 영상을 바꾸거나 지울 수 있다** — 체인에 남는 것은 링크뿐, 영상 내용의 지문(SHA-256)은 남길 수 없다. ③ 환불 책임은 판매자. 구매 확인 화면에 「영상은 판매자가 올린 곳(Vimeo 등)에서 재생돼요. 판매자가 영상을 바꾸거나 지우면 볼 수 없어요. 레이븐볼트는 돌려줄 수 없어요」를 신뢰 띠 아래 고정으로 |
| 안전 장치 | 링크 형식·도메인 검사(막힘), 예고편과 본편이 같은 링크면 경고, 본편 링크가 공개 채널 링크(`watch?v=` 공개)면 「누구나 볼 수 있는 링크예요」 경고, 나머지(이름·체인 조회·소각·메인넷)는 같은 칩 |

## 15. 장르(`src/drop-genre.ts`)

- **이름에는 넣지 않는다**(이름은 영구·30자 한도·목록이 바뀌면 틀린 말이 됨). 서명된 매니페스트 v3 의 `genre = { main, tags }` — `main` 은 종류별 고정 목록의 id(장터 필터 키, 영구), `tags` 는 자유 태그 최대 3개(검색용). 검사: `validateGenre`(모르는 칸·목록 밖 id·태그 4개↑·제어/양방향 문자 거절), 매니페스트 v3 검사에 포함(시험).
- 목록(보이는 말만 고칠 수 있음): 음악 — 팝·힙합·R&B·록·발라드·일렉트로닉·재즈·클래식·CCM·찬양·포크·어쿠스틱·OST·동요 / 게임 — 액션·퍼즐·육성·RPG·전략·캐주얼·스포츠·리듬·교육 / 책 — 소설·에세이·시·신앙·어린이·만화·학습·자기계발·실용 / 티켓 — 공연·강연·모임·수업·경기·전시 / 디지털 — 그림·사진·배경화면·서식·소리·문서 / 영상(제안) — 강의·운동·영화·단편·다큐·어린이·뮤직비디오. 모두 「그 밖의 ○○」 포함.
- **한 번 탭으로 고른다**: 미리보기 아래 「장르」 줄(모양·색과 같은 줄 묶음, 펼치지 않아도 보임). 다시 누르면 해제.
- **라비 추천(제안 → 확인)**: `suggestGenre` 가 제목·설명·파일 이름의 낱말로 고르고 이유 한 줄을 단다(「라비 추천: 힙합 — 「rap」이(가) 보여서요」). 점선 단추로 보이고, **눌러야 적용**된다. 확신이 없으면 아무것도 추천하지 않는다. 라비 AI 가 붙으면 같은 모양(`GenreSuggestion`)으로 돌려주면 화면은 그대로다.
- **장터**: `genre.main` 으로 종류 탭 아래 장르 칩 필터·「둘러보기」(장르별 줄), `tags` 는 검색어. v3 를 읽게 되기 전(§8)에는 판매자 화면에만 있다.

## 16. 라비가 돕는 설정(원칙: 제안 → 확인 후 적용)

대표 기준: 「동네 당근처럼 쓰기 쉽고 예쁘고 반응 빠르게, 모든 설정은 라비가 도울 수 있게」. 이 화면에서 라비가 손댈 수 있는 것은 전부 **제안 단추**로만 나타나고 사람이 눌러야 바뀐다(되돌리기 = 다시 누르기/고급에서 고치기).

|---|---|---|
| 종류·형식 | 파일로 자동(§4), 모를 때 한 번 묻기 | 묻기 화면에 「라비 생각: ○○ 같아요」 강조(다음 단계) |
| 장르 | — | **라비 추천 단추(구현됨, 낱말 기반)** |

| 가격 | 종류별 기본값(초안) | 비슷한 상품 가격대 안내(장터 목록이 생긴 뒤) |
