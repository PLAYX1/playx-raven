# 창 모드 체계 (레이븐볼트 데스크탑)

대표 요청(2026-10-11): 「애플 뮤직처럼 큰 것·중간·작은 것·엄청 작은 것·대기화면 등 디자인을 다 고려해 봐.
컴퓨터로 일하는 사람들은 화면 한쪽에 메뉴바만 놓고 싶어 하지 않을까?」 + 「창을 작게 줄이면 자동으로 작은 모드가 반영되게 하면 되지 않나?」

시안 갤러리: `artifacts/modes-gallery/index.html`(PNG 6장: 테마·가림·판매자·한/독/러) · 레이아웃 규칙: `docs/design/layout-tokens.md` · 미니 창: `docs/mini-window.md`.

**대원칙 셋**
1. **돈이 움직이는 일은 큰 창의 명시적 확인 화면에서만.** 작은 모양(작은 창·칩·메뉴바·도킹 바·대기화면)은 전부 읽기 전용 — 보내기·서명·복구 단어·비밀번호 입력이 없다. 코드로 막는다(IPC 문지기 + 최소 capability).
2. **금액 가리기 기본 켬, 가림은 Rust 에서.** 작은 모양들은 가려진 한 장(`mini::snapshot`)만 받는다. 주소·txid 는 어디에도 안 싣는다.
3. **정체성 유지.** 색·라비·글꼴은 그대로. 바꾸는 것은 크기별 정보 위계와 움직임의 물성뿐.

## 3. 모드 전환 모델

- **한 설정 「표시 방식」**(설정 화면, `#display-mode-card`): 큰 창 · 작은 창 · 칩 · 메뉴바만 + 「대기화면 켜기」 단추. 더 고르기: 메뉴막대 글자(새 소식 수/잔액/없음, 맥만) · 독 숨기기(맥만) · 대기화면 어둡게 할 시간 · 번인 막기.
- **트레이(메뉴막대) 메뉴**: 「표시 방식」 묶음(같은 네 모드 + 대기화면 켜기). 창 없는 모드일 때 메뉴 맨 위에 읽기 전용 요약 세 줄(노드 · 잔액 · 새 소식).
- **대기화면은 「모드」가 아니라 「동작」** — 켜고, 아무 키로 끈다. 끄면 원래 모드로 돌아간다(큰 창 모드면 큰 창이 앞으로).
- **단축키(제안, 미구현)**: ⌘/Ctrl+Shift+M 작은 창 토글 · ⌘/Ctrl+Shift+L 대기화면. 창 밖에서도 먹으려면 `tauri-plugin-global-shortcut` 이 필요하다(새 의존성·권한 — 대표 결정). 키보드로 여는 동작이라 **애니메이션 없음**.
- 돌아오는 길은 늘 둘 이상: 트레이 메뉴 「큰 화면 열기」 + 미니/칩 「큰 화면」 단추(칩은 누르면 S 로 펼친 뒤). 트레이를 못 쓰는 컴퓨터(일부 리눅스)에서는 큰 창 외 모드를 **거절**한다(돌아올 길이 없어지므로).

## 4. 자동 전환(창 크기로) — 설계 + 판단 함수

대표 질문 「창을 작게 줄이면 자동으로 작은 모드가 반영되게 하면 되지 않나?」 → **된다. 단 규칙 넷.** (`src/auto-mode.ts`, 시험 `scripts/window-modes.test.mjs`)

1. **문턱 + 히스테리시스**: 큰(≥960×560) → 중간(≥600×420) → 작은 L(≥340×240) → M(≥280×120) → S(≥200×52) → 칩. 내려갈 때는 문턱, **올라갈 때는 문턱+24px** — 문턱 근처에서 끌어도 깜박이지 않는다(시험: 950→970 은 중간 유지, 990 에서 큰 창).
2. **핀(고정)이 이긴다**: 설정·트레이에서 사람이 고른 모드는 자동이 건드리지 않는다.
3. **돈·보안 화면 진행 중에는 모드를 바꾸지 않는다**: 보내기 검토·확인, 복구 단어 보기·입력, 비밀번호, 서명 대기. 크기를 줄이면 **같은 창 안에서 「안전 축소」**(같은 화면을 한 줄 세로 배치, 입력값 유지)만 한다. 그 화면을 벗어난 뒤 다음 크기 변화 때 다시 판단.
4. **전환은 짧고 중단 가능**: 160ms 크로스페이드(ease-out). 끌기 도중에는 바꾸지 않고 손을 뗀 뒤 한 번(끌기는 1:1 이어야 한다). 움직임 줄이기면 즉시.

**왜 아직 창에 안 붙였나**: 큰 창 최소 폭(720, `tauri.conf.json`)을 낮춰야 하고, 큰 창 → 미니 창(다른 웹뷰)으로 넘어가는 순간의 포커스·입력 보존을 `main.ts` 에서 다뤄야 한다(다른 에이전트가 통합 중인 파일). 다음 단계로 남긴다. 「중간」은 같은 창 안 CSS 라 먼저 붙일 수 있다.

**크기별 정보 우선순위**(`PRIORITY`):

| 단계 | 보이는 것(순서대로) |
|---|---|
| 큰 | 잔액 · 알림·할 일 · 최근 거래 · 라비 · 가게 매출 · 더 보기 |
| 중간 | 잔액 · 알림·할 일 · 최근 거래 3 · 라비(작게) |
| 작은 L | 잔액 · 들어오는 중 · 최근 변화 4 · 노드 · 잠금·깨움 · 오늘 판매(판매자) |
| 작은 M | 잔액 · 최근 변화 3 · 노드 |
| 작은 S | 상태 점 · 잔액 또는 새 소식 N |
| 칩 | 상태 점 · 잔액(가림이면 ••••) |

## 5. 대기화면 — 실제 시나리오에서 나온 규칙

- **가게 계산대 옆 모니터**: 손님도 본다 → 가림 기본, 판매 「건수」만 크게, 금액은 가림을 끈 사람만. 누를 것 0개(손님이 건드려도 할 수 있는 것이 「돌아가기」뿐, 돌아가면 큰 창이 나오지만 보내기는 잠금·확인 화면 뒤).
  ✅ 대표 결정(2026-10-11 「(나)」): 대기화면에 **들어가는 순간 지갑을 잠근다**(Rust `app_lock`, 보내기·서명·복구 단어 IPC 거절). 「아무 키로 돌아감」은 인증 없이 **잠긴 기본 화면**으로 돌아가고, 지갑을 다시 쓰려면 지갑 암호. 설계·IPC 표: `docs/design/lock-and-dark.md`.
- **사업장·거래소 큰 화면**: 멀리서 읽힘 — 숫자 40~140px(vmin 비례), 시계는 분 단위.
- **번인 방지**: 순검정 배경 · 순백 대신 회백(#d9d9e0) · 1분마다 묶음을 ±24px 옮김(결정적 식, Rust·화면 같은 값 — 시험) · 이동은 1.6s ease-in-out(눈에 안 띄게, Web Animations — style 속성 안 남김) · 여백(32px)이 이동 폭보다 커서 화면 밖으로 안 나감(관문이 잡았던 버그).
- **밤 시간(기본 22~7시)**: 글자색만 낮춤(14.9→8.4:1, 흐린 글자 7.6→5.0:1). 불투명도로 흐리면 1.2:1 이 돼 못 읽는다(시험이 잡음).
- **아무 키·클릭으로 돌아감, 마우스 움직임은 무시**(계산대에서 스쳐도 유지).
- 확인 필요: 대기화면이 켜진 동안 **모니터 절전**을 막지 않는다(OS 설정 따름). 막으려면 `awake.rs` 와 별도의 디스플레이 깨움이 필요(대표 결정).

## 6. 카드 홈 · 라비가 고르는 위젯 (설계 + 검증 함수)

참고 자료(Nothing·Rabbit·생성형 UI — 사실 여부 미확인)는 **영감만**: 미니멀·단색·카드 단위·대화 중심. 특정 제품의 도트 글꼴·로고·트레이드 드레스는 쓰지 않는다.

- **카드 = 정보 단위**: 잔액 · 최근 변화 · 판매 현황(판매자) · 재고(판매자) · 노드 · 라비 · 시계. 같은 카드가 칩·S·M·L·대기화면에서 다른 필드를 보인다(`cardFields`). 사용자가 카드 순서·표시를 고른다(편집 모드 — 갤러리 8번).
- **라비는 고정 카탈로그에서 고르고 값만 정한다**(`src/card-catalog.ts` `validateLayout`):
  모르는 카드·모르는 칸(html·url…)·열거 밖 값·판매자 전용(판매자 꺼짐)·중복·8개 초과는 버리고 **버린 이유를 미리보기에 보여 준다** → 사람이 「추가」를 눌러야 반영.
  카탈로그에 「보내기·서명·사기·팔기」 카드는 **없다**(시험이 이름까지 검사).
- **생성형 UI(AI 가 화면을 실시간으로 그림)는 지갑 본체에 쓰지 않는다**: 지갑의 신뢰는 「같은 자리에 같은 단추가 같은 일을 한다」에서 온다. AI 가 그린 송금 흐름은 피싱 화면과 구별이 안 된다. 허용 범위는 **돈과 무관한 대시보드 배치**(카드 고르기·순서)까지.
- 돈이 움직이는 동작은 대화에서 시작해도 **늘 큰 창의 명시적 확인 화면**으로 넘어간다(라비가 금액·주소를 채워 줘도 확인 단추는 사람이).

| 미니 창 끌기 | OS 기본 | `startDragging`(1:1, 잡은 자리 유지) | 스프링·관성은 OS 창 이동이라 웹에서 못 줌 — 가장자리 「자석」 붙임은 다음 단계(Rust 에서 위치 스냅) |
| 움직임 줄이기 | 전부 | 이동 없음·즉시, 색·불투명만 | |

**더 움직일 만한 곳(목록만)**: 칩→S 펼침 시 글자 크로스페이드(창 크기는 OS) · 새 입금 때 잔액 숫자 짧은 강조(200ms 배경 깜빡임 대신 색 변화) · 메뉴바 모드 진입 시 큰 창이 트레이 쪽으로 줄어드는 「지니」는 **하지 않음**(OS 가 안 줌, 흉내 내면 느림).
**움직이면 안 되는 곳**: 보내기 검토·확인, 복구 단어, 금액 입력 — 정적이어야 읽힌다.

## 10. 못 해 본 것 (실제 OS 창)

앱을 실제로 띄워 보지 않았다 — 아래는 코드·문서 근거뿐:
- 칩 160×40 무테 창이 맥·윈도우 최소 창 크기 제한에 걸리지 않는지(윈도우는 무테 창 최소 크기가 있을 수 있음 — 확인 필요).
- 메뉴바만: `set_dock_visibility(false)` 뒤 큰 창을 열었을 때 독이 돌아오는지(큰 창 포커스 때 되돌리게 해 둠), **독 숨김 상태에서 큰 창의 ⌘C/⌘V 가 먹는지** — 확인 필요(메뉴 단축키 처리).
- `set_show_menu_on_left_click` 런타임 변경이 맥·윈도우에서 즉시 반영되는지.
- 트레이 메뉴 `prepend_items`/`remove` 로 요약 줄을 넣고 빼는 것이 각 OS 메뉴에서 깜박임 없이 되는지.
- 대기화면 전체 화면: 맥은 새 Space 로 넘어간다(애니메이션 포함). 여러 모니터에서 큰 창이 있는 모니터로 가는지. 캡처 보호(`content_protected`)가 맥 15+ ScreenCaptureKit 에서도 먹는지 — 확인 필요.
- 도킹 바: Tauri 2 에 화면 작업 영역 예약 API 가 없다. 윈도우는 Win32 `SHAppBarMessage` 를 직접 불러야 하고(새 unsafe FFI), 맥은 공개 API 가 없는 것으로 안다(확인 필요). 대안: 미니 S 를 가장자리에 자석처럼 붙이기.
